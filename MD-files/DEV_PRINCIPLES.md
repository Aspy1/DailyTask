# DEV_PRINCIPLES.md — 可迁移的通用开发准则

> **定位**：从本项目的一轮完整整改中提炼出的、**不依赖具体项目**的工程准则。
> 目标是"复制到任何项目都成立"。凡涉及本项目专有的路径/文件名，一律写成通用表述。
>
> 与 `CODE_STANDARDS.md` 的分工：
> - `CODE_STANDARDS.md` = 本项目的**可检查规则**（Q-xxx，含现状）
> - **本文件** = 这些规则背后的**通用原理**，以及"怎么定规则、怎么执行规则"的方法
>
> 每条尽量可执行、可验证。

---

## 0. 四条总纲

1. **规范必须可执行**——不能被机器检查的规范，等于没有规范。
2. **先度量，再重构**——用数据排优先级，不凭感觉。
3. **单一真值**——同一事实只有一个权威来源，其余由它派生。
4. **一次一类改动，独立提交**——便于回溯与二分定位。

---

## 1. 怎么定规范、怎么让规范生效

**1.1 规范写成「可检查的语句」**，模板：

```
规则（祈使句） → 为什么 → 如何检查（命令/工具） → 现状（达标/违规）
```

没有"如何检查"的条目，只是口号。

**1.2 规范要落成配置，而不是靠自觉。**
能写进 linter / CI / pre-commit 的，就别写在文档里让人记。
（本项目把"UI 层允许盲捕获"写成 `per-file-ignores` + 理由注释，而不是靠人记得。）

**1.3 允许「显式豁免 + 理由」，但豁免必须集中、可见、可审计。**
豁免散落在代码里就成了技术债的遮羞布；集中在配置文件里才可被 review。

**1.4 门禁分两步走：先只报告，后阻断。**
第一步只产出基线（让人看到全貌、排序），第二步才在 CI 里 fail。
一上来就阻断，会逼着人 `--no-verify` 绕过。

**1.5 规则集要钉死，别用工具默认值。**
工具的默认规则集会随版本变化；"基线"如果依赖默认值，明年就不可复现。
❌ 反例：直接 `ruff check` 靠默认集，得到 244 项；显式 select 后是 315 项——**同一份代码、两个"基线"**。

**1.6 门禁要能区分"违规"与"豁免"**，并让豁免成本低于违规成本（否则大家会选择违规）。

## 2. 度量驱动

**2.1 先建基线**：复杂度、死代码、静态检查、覆盖率——四件套。
```
复杂度:  radon cc -s -n C <src>          # 只看 C 级及以上
死代码:  vulture <src> --min-confidence 80
静态检查: ruff check --statistics
覆盖率:  pytest --cov=<pkg>
```

**2.2 用数据排优先级**，并对"什么是真问题"有判断：
- 真 bug（并发竞态、闭包捕获、静默吞异常）> 复杂度长尾 > 纯风格
- 覆盖率低时，"重构"的风险高于收益——先补关键路径测试

**2.3 度量必须可复现**：固定工具版本 + 显式配置 + 记录在案的命令。
否则数据只是"某次运行的快照"，无法用于比较。

**2.4 看趋势不看绝对值。** 从 315 → 0 有意义；某次是 244 还是 251 没意义。

---

## 3. 单一真值（Single Source of Truth）

**3.1 一份事实只能有一个权威来源。** 其余副本必须由它**生成**，或明确标注"派生"。

**3.2 生成 + 守卫测试。**
- 用脚本从真值生成文档/配置；
- 写一条测试断言"生成结果 == 文件内容"，防止有人手改生成区。
（本项目：令牌真值 → 生成设计文档 + 同步测试。）

**3.3 重复的手写副本必然漂移。**
本项目实例：设计令牌同时存在于"规格文档"和"代码常量"里，几个月后就 `bg_surface` 一个 `#E8E5DE` 一个 `#E0DDD6`。
**判断信号**：如果两处内容"本该相同"，就一定会有人只改一处。

**3.4 版本号、常量阈值、外部契约（命令/接口清单）都是"单一真值"的典型候选。**

---

## 4. 数据与状态

**4.1 原子写入。** 写临时文件 → 备份 → `os.replace`；对 Windows 的 `PermissionError`（杀软/索引器）做短暂重试。

**4.2 单写者原则（并发下最重要的原则）。**
跨线程改共享数据时，**优先把写操作收敛到单一线程**，而不是加锁。
本项目实例：把"worker 线程直接改内存模型"改成"worker 只跑命令，数据的重载与通知回到主线程"——比加锁简单且更安全。

**4.3 类属性做缓存 = 全局可变状态，禁止。**
即使当前只有单实例，它也会在测试、线程、未来多实例下出问题。改为实例属性。

**4.4 显式落盘。** 内存改动不自动保存，必须显式 `save()`——避免"以为保存了"。

**4.5 路径用**绝对**路径，禁止依赖 CWD。**
自启/计划任务/CI 的 CWD 往往不是项目根（Windows 下甚至可能是系统目录）。
`Path(__file__).resolve().parent...` 永远比 `Path("data/...")` 安全。

**4.6 数据目录与代码目录分离**；用户数据（含密钥）永不进发行版；密钥不进 git/日志。

## 5. 并发

**5.1 线程入口必须捕获异常**，不允许异常逃逸（会导致线程静默死亡）。
**5.2 禁止 `QThread.terminate()`**（与 `pthread_cancel` 同类的强杀）；改用"丢弃过期结果"。
**5.3 worker 生命周期必须回收**（`deleteLater` / 单一归属），禁止反复 new 不释放。
**5.4 一个资源槽位不要复用给多种任务。**
本项目实例：`now` 与 `7d` 两个天气请求共用一个 worker 槽 → 第二个被 `isRunning()` 挡掉 → **功能静默失效数月**。
**5.5 进程级全局状态（`sys.stdout`、`os.environ`）在 worker 里改动要加锁串行化**；能改成"返回值"就别改全局。

---

## 6. 错误处理

**6.1 禁止静默吞异常**（`except ...: pass`）。
它把"真 bug"伪装成"正常流程"，是"AI 说做了、实际没做"这类故障的温床。

**6.2 盲捕获只允许用于「显式边界」**：线程入口、事件循环槽、第三方/插件代码、外部服务。
且必须：**写理由注释 + 显式豁免标记**。

**6.3 能收窄就收窄。** 记住常见等价关系：
`requests.RequestException` ⊂ `OSError`，所以 `except (OSError, ValueError, KeyError, TypeError)`
通常足以覆盖"网络 + JSON 解析 + 字段缺失"。

**6.4 注意 linter 的盲区。**
`ruff S110` 只报"裸 `pass`"；**具名 `except ValueError: pass` 同样是静默吞异常却不会被报**。
本项目用 AST 扫出 40 处 vs linter 报的 24 处——差的 16 处才是更隐蔽的。

**6.5 异常处理的两条判据必须**二选一且均可执行**：收窄，或"标注边界"。
只写"禁止盲捕获"而没有豁免通道，规则必然被绕过。

## 7. UI 与设计令牌（可迁移到任何有设计系统的前端）

**7.1 令牌单一真值 + 分层**：原始色板（palette）→ 语义角色（bg/fg/border/state）→ 组件（btn/card/nav）。
组件只允许引用语义/组件层，禁止直接引用色板。

**7.2 命名用受控词表**，统一前缀/后缀：
`<domain>_<variant>_<property>_<state>`（如 `btn_primary_bg_hover`）。
同一用途必须同前缀——否则脚本和人都无法判断"这里该用什么"。

**7.3 样式只走令牌，禁止字面量**（`#hex`/`rgb()`/`Npx`）。
违规往往暴露"缺失的令牌"——补令牌比就地写字面量更有价值。

**7.4 遵守框架限制。**
本项目：Qt 的**类名 QSS 选择器在 Windows 上不生效**，必须用 `#objectName`。
这类"框架怪癖"要写进规范，否则每个新人都会再踩一次。

**7.5 视觉变化要显式列出。**
样式整改会带来肉眼可见的变化（尤其"修好了"的变化，比如卡片终于有了圆角）。
把它列成清单交给负责人目视确认，而不是默默改掉。

## 8. 验证与测试

**8.1 每次改动的验证顺序**（缺一不可）：
```
compileall → ruff → pytest → 应用级 import 冒烟 → 项目专有检查器（如令牌）
```

**8.2 覆盖率低时，优先给「关键路径」补测试**：
命令层（易测、无 UI）、纯函数/解析器、外部脚本。
先补"能被 CI 跑、无外部依赖"的部分。

**8.3 契约测试防漂移**：
凡是"两处必须一致"的地方（提示词 ↔ 命令实现、文档 ↔ 代码），写一条测试断言一致。

**8.4 运行时冒烟 > 静态检查。**
能离屏真实构建对象就跑一遍（本项目：离屏建 QApplication + 数据管理器 + 控件，调一次 `_refresh()`）。
静态检查过 ≠ 不炸。

**8.5 批量改写脚本必须「先空跑核对计数」，再落盘。**
计数与预期不符就是信号，立刻停。
> 本项目实例：用 `tokenize` 拆语句时，因未把 f-string 内部计入嵌套深度，一次"拆"了 408 处（应为 49），污染了样式串。**先 dry-run 就不会发生。**

**8.6 自动修复要分级。**
`--fix`（安全）与 `--fix --unsafe-fixes` 分开跑；删导入、删变量这类"看起来安全"的自动修复，
改完必须立刻全量验证（删掉的可能是"只有副作用、没有引用"的调用）。

## 9. 文档

**9.1 只写代码表达不了的东西**：跨文件时序、不变量、为什么这么设计、外部契约。
签名/参数/返回值/字段结构**不要抄**——代码里已经有了，抄一遍只会漂移。

**9.2 文档体系固定、职责单一。**
每个文件回答一类问题，不在两处回答同一个问题：
`流程/环境` · `架构原理` · `规范` · `计划/体检` · `坑` · `变更史`。
> 反面：为每个源文件写一份"函数合同"文档——生成的是骨架（"核心逻辑：参见源码"），
> 还会**系统性失实**（把只读属性写成"有副作用"），比没有文档更毒。

**9.3 索引类文档要能被校验，或干脆由脚本生成。**
写死的行号、手抄的文件清单，一定会过期。

**9.4 变更要留"为什么"，不只是"改了什么"。**
变更史记事实；决策记录（ADR 风格）记理由。**理由才是未来最需要的。**

## 10. 与 AI Agent 协作的工作方式

**10.1 把"流程"写进项目级指令文件**（`AGENTS.md` 之类），而不是每次口头交代：
必须读哪些文件、复杂度分档、完成后做什么（验证/文档/提交）。

**10.2 定义"完成"**（DoD）并逐条可判定：
语法过 · 测试绿 · 冒烟过 · 文档同步 · 有变更记录 · 已提交。

**10.3 边界约束要前置**：
工作区范围、哪些目录不可动、密钥禁令、依赖安装位置（先查本机已有，没有再装）。

**10.4 大改动拆成"可独立合并"的小步**，每步一个提交、一条消息说清一件事。

**10.5 怀疑"静默失效"时的排查顺序**（本项目的高频根因）：
① 异常被吞 → ② 资源槽复用/被挡住 → ③ CWD 相对路径 → ④ 并发竞态 → ⑤ 信号声明了没 emit。

## 11. 反面清单（本项目已踩过，通用化表述）

| 反模式 | 后果 | 通用教训 |
|---|---|---|
| 声明了但从未触发的回调/事件 | 绑定成功却永不执行 | 新增事件必须有发射点，且可被搜索验证 |
| 批量文本替换（含"替换目标出现在被替换函数内部"） | 自调用死循环 | 涉及自身引用的改动必须精确定位 |
| 用 `长度+1` 生成 ID | 删除后 ID 冲突 | ID 生成必须查重取最大+1，或统一由一处生成 |
| 手写参数解析器绕过默认值机制 | 缺省参数全线崩溃 | 别手搓框架已有的机制 |
| 把事件/信号当数据通道传字符串 | 脆弱、难追踪 | 数据走参数/返回值 |
| 依赖 CWD 的相对路径 | 自启/CI 下写错位置 | 一律基于 `__file__` 的绝对路径 |
| 同一能力多套实现 | 必然漂移、改一处漏一处 | 一个外部能力只保留一套适配 |
| 类属性当缓存 | 跨实例/跨线程污染 | 状态进实例 |
| 用 `terminate()` 杀线程 | 资源泄漏/未定义行为 | 让任务自然结束，丢弃过期结果 |
| 面向 token 的批量改写忽略 f-string 嵌套 | 破坏字符串内容 | 先 dry-run 核对计数 |
| 生成文档与手写文档并存 | 内容漂移、误导读者 | 单一真值 + 生成 + 守卫测试 |

## 12. 可直接复制的落地清单

新项目起步时，按此顺序建立地基：

1. **环境与依赖**：虚拟环境 + 锁定文件 + `requires-python`；依赖先查本机已有。
2. **指令文件**：`AGENTS.md`（流程 / 环境 / 边界 / DoD）。
3. **规范文件**：`CODE_STANDARDS.md`，条目 = 规则 + 为什么 + 如何检查 + 现状。
4. **度量基线**：装 `ruff` / `radon` / `vulture` / `pytest-cov`，**钉死规则集**，跑一次基线存档。
5. **测试脚手架**：最小冒烟测试（关键路径 + 契约测试），确保 `pytest` 绿。
6. **自动检查**：把规范里"可机检"的部分写进配置（lint 选择、per-file-ignores、CI 步骤）。
7. **文档真值**：把会变的手写副本换成"生成 + 守卫测试"。
8. **门禁**：先只报告 → 清理 → 再在 CI 阻断。

> 一句话：**先把"怎么算做对了"变成机器能判断的东西，再开始改代码。**
