# 2026-10-16 · 学期参数（16 周 + 期末周）与撞课提醒

## 起因

用户两条需求：

1. **学期参数按校历口径调整**：每个学期 16 周；秋季学期一般 9/21 起、1/8 上完最后一门课后
   进入**期末周**（"据此调整设置"）；
2. **处理"同一时段有两门课"**（选修课过多 / 有重修）→ **提醒用户请假**。

用户拍板：默认开始日**按季节预设（秋 9/21、春 3/2）**；撞课提醒**只做应用内**
（不动邮件摘要，本轮也不做"标记已请假"）。

## 变更清单

### 1. 学期参数

| 项 | 旧 | 新 |
|---|---|---|
| 教学周默认 | 20 | **16** |
| 期末周 | 无 | **默认 1**（0–6 可调） |
| 新建学期默认开始日 | 下一个周一 | 7–12 月 → 当年 **9/21**；1–6 月 → 当年 **3/2** |

- 新状态 `exam`：教学周上完、期末周内 → 状态栏与周标签显示 **"期末周"**，**仍显示最后一周课表**
  （不空白）；此时 `week_number_for()` 返回 `None`（期末周确实不上课）。
- `end_date` = **含期末周**的学期最后一天；新增 `teaching_end_date`；"已结束"只在期末周过后。
- **用户给的例子钉进测试**：`2026-09-21`（周一）+ 16 教学周 → 第 16 周周五 = **2027-01-08** ✓。

### 2. 撞课（同一时段两门课）

**数据不用改**：两门课本来就是两条记录。缺的是三件事，而原来的行为是**静默丢数据**：

> `setCellWidget(row, col, chip)` 一格只能有一个 widget —— 第二门课**直接覆盖**第一门，
> 课表上看起来"只有一门课"。`_cell_courses[(row, col)]` 同理只留最后一门（`ERRORS #038`）。

- 新增纯规则 `models/course_rules.py`：
  `conflicts_by_cell(courses, week, period_count)` → `{(day, 节次): [课程, …]}`（只留 ≥2 门的格子）。
  规则含：周次范围、`excluded_weeks`、单双周、`end` **闭区间**、节次上限。
- **周视图**：冲突格渲染 `_ConflictChip`（`⚠ 两门课冲突` + 两门课名），按两门课**合起来的跨度** `setSpan`；
  右键菜单逐门课提供"查看事项"。
- **日视图**：该时段卡片顶部加 `⚠ 本时段有两门课，记得请假`。
- 只做应用内（用户选择）；`excluded_weeks` 已具备"请假那周不再算冲突"的能力，
  将来要加"标记已请假"只需在冲突块右键加一项。

### 3. 测试套件偶发崩溃的根治（`ERRORS #039`）

改完冲突渲染后跑全量测试，**偶发** `access violation`（崩点每次不同）。排查与修复：

- 用"多轮跑 + 统计崩溃率"把偶发变成可测量（约 25%）；`-v` 定位到崩溃**紧跟**某几个测试之后
  → 是**累积状态**，不是某条测试；
- 对照实验：给 teardown 加 `gc.collect()` → 崩溃率 25% → **100%**，这个"变坏"指出真因在**销毁路径**：
  我 teardown 里的 `deleteLater()` + 强制处理 `DeferredDelete` 会删掉 **Python 仍持有的** C++ 对象
  → 之后 Python 侧再删一次 = 双重释放；而任何**嵌套事件循环**都会把它翻出来；
- 修复：teardown 只 `sendPostedEvents(DeferredDelete)`（处理被测代码自己删的对象），
  **不**替 Python 删仍被持有的对象、**不** `close()` 顶层控件（`closeEvent` 有副作用且慢）；
  菜单那条测试改成确定性断言（不再起事件循环）；
- 顺带：`detect-secrets` 全仓扫描从单测挪到只测比对逻辑（8.9s → 0.01s）。
- 验证：**8 轮 × 2 配置 0 崩溃**；全量耗时 37s → 27s。

## 一个值得记下的坑：两种"方块字"要分清
- **真问题**（`ERRORS #036`）：区域 `zh_HK` 的 CJK 数字 —— `QDateEdit.text()` 里**就是**
  `〢〇〢〦-〡〇-〡〩`，与渲染平台无关 → 必须修。
- **离屏假象**：emoji/符号（`⚠ 📖 ▶ ● ✓`）在 offscreen 平台缺字体回退 → 显示成方块，
  但**真实平台全部正常**（已用真实平台 + 不上屏 `grab()` 验证）→ 不该"修"。

判断方法：看 `text()` / `toPlainText()` 的**真实字符串**；只有渲染层面的差异才可能是平台假象。

## 决策原因

- **为什么"期末周"是独立状态而不是把总周数改成 17**：教学周和期末周的**含义不同** ——
  教学周有课、期末周没课但有考试。混成一个数字会让"第几周"失去意义
  （第 17 周该不该有课？课表该显示哪一周？），独立状态一句话说清。
- **为什么默认开始日"不往后推一年"**：10 月建学期时，默认给"当年 9/21"才是用户**正在过的**
  那个学期；给明年 9/21 反而要手动改。
- **为什么冲突检测抽成纯模块**：它要同时服务周视图（渲染）与日视图（提示），
  而且规则（闭区间、单双周、排除周）必须只有一份实现 —— 与 `semester.py` 同一套路。
