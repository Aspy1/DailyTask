# 2026-10-19 R3：日期驱动的状态必须跨天生效（三种日期都算）

## 起因

`PLAN.md` P22 批次一第三条（`REVIEW.md` R3）。

`derive_status()` **早就**支持三种日期：

| 日期 | 语义 |
|---|---|
| `membership.expires_on` | 会员到期（要续费） |
| `expires_on` | 保质期（药品临期换新） |
| `runs_out_on` | 预计用完（按时间估算补货） |

但**入口只认第一种** ✗ —— `has_expiry()` 只查 `membership.expires_on`，于是
`load()` 与 `effective_status()` 对顶层日期一律走"用存下来的 `status`"：

```
存盘 status=充足，expires_on=昨天
  derive_status()      → 需购     ✓ 规则本身对
  effective_status()   → 充足     ✗ 入口没接上
```

后果：**界面、AI 摘要、补货列表、每日提醒全部漏报** ✗，而且**重启也治不好** ✗
（`load()` 同样只重算会员）—— 只有会员那种日期是活的。

## 改法

`has_expiry()` → **`has_time_status()`**：三种日期任一即为真。

```python
if InventoryModel.membership_of(item).get("expires_on"):
    return True
return bool(item.get("expires_on") or item.get("runs_out_on"))
```

`effective_status()` / `load()` 改用它，并且：

- **日期驱动的** → 按日期重算（快照会过期）；
- **其余** → 保留存下来的 `status`（用户可能用 `--status` 手动改过 —— 2026-10-18
  那个 `test_actions_smoke` 回归不能被破坏）；
- **`ignore_low_stock`（显式豁免）** → 连日期驱动也不重算，原样返回 —— 与 `load()` 同一口径。

> 审查的原话："判据必须是**有没有日期**，不是**是不是会员** —— 否则为了保住手动状态，
> 会把所有非会员的自动状态一起冻住。" 这正是 R3 的成因。

## 验证

新增 `tests/test_inventory_time_status.py`（**6 条**），核心是**跨天**（审查要求的口径）：

- `has_time_status` 三种日期都算、没有日期不算；
- 保质期过了 → `需购`（存盘是"充足"）；预计用完日过了 → `需购`；
- **没有日期的手动 `status` 不被覆盖**（守住老回归）；
- `ignore_low_stock` 仍然豁免；
- 三个**真实出口**：重新读盘后 `status` 已重算 + `need_restock` 列到它 + AI 摘要出现"需购"。

