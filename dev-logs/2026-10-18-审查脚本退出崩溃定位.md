# 2026-10-18 审查脚本"退出崩溃"定位

用户问的是审查材料里那条自述：*"渲染脚本完成图片输出后出现原生进程退出异常，尚未定位；不能据此
声称正式应用存在同样崩溃"*。**结论：确认是审查脚本（测试脚手架）自己的问题，产品退出路径是干净的。**

## 复现

```bash
cd .pytest_cache/ui-audit-20261018
../../.venv/Scripts/python.exe audit.py
# → AUDIT_COMPLETE 38 screenshots
# → Segmentation fault（退出码 139）
```

崩在**最后那句 `os._exit(0)`** 上，不是渲染过程：脚本已经把 152 张图和 metrics 全写完了。

## 对照实验：产品自己的退出是干净的

| 场景 | 退出码 |
|---|---|
| 起 `MainWindow` → `close()` → `app.quit()`（**正式应用走的那条**） | **0** |
| 起 `MainWindow` → `os._exit(0)` | **0** |
| 再加 4 个对话框（show/hide）+ 反复切浅深主题 → `os._exit(0)` | **0** |
| 再加 monkeypatch 的 `QDialog.exec` + `edit_tags_dialog` | **139** |
| 同上但只跑 `email_reminder_dialog` | **0** |

## 定位结果

- **不是** monkeypatch 本身：裸 `QDialog` + `QDialog.exec = lambda self: 0` → 退出码 0
- **不是** `QDateTimeEdit(setCalendarPopup=True)`（会造弹出日历）：单独测 → 0
- **是** `edit_tags_dialog`：只跑它就 139，邮件弹窗单独跑是 0

两者的差别：改标签弹窗里有**自绘控件**（`RoundedLineEdit` / `RoundedButton`）和
`QListWidget`；邮件弹窗只有原生控件 + 一个日期控件。

**触发条件需要脚手架的两个动作同时在场**：把模态的 `QDialog.exec` 换成 `show()/hide()`
（模态循环从没跑过，对话框就一直挂在"已显示但没人管"的状态）+ 最后用 `os._exit(0)` 硬退
（跳过所有 C++ 析构与 Qt 的销毁流程，只剩 DLL detach）。这正是审查自己写的
"独立复现脚本显式退出，亦不验证 Qt 正常销毁流程"。

## 结论与建议

1. **产品不需要改**：正式应用的退出（托盘退出 → `close()` → `quit()` → `flush_on_exit`）
   实测退出码 0；审查自己也明确说不能据此声称产品有同样崩溃 —— 现在有证据了。
2. **要改的是审查脚手架**（`.pytest_cache/ui-audit-20261018/audit.py`，不进版本库）：
   把 `QDialog.exec` 的 monkeypatch 换成"真跑模态 + 定时关掉"，或在截图后
   `dlg.close()` + `dlg.deleteLater()` 再 `settle()`，而不是直接 `os._exit(0)`。
3. 如果以后还要跑这类批量渲染，**先 `close()` 再退**，别用 `os._exit` 跳过销毁 ——
   否则这类"退出即崩"会一直复现，且很难判断是不是产品的问题。
