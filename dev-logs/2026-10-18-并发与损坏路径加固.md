## 变更清单

| # | 问题 | 修法 |
|---|---|---|
| **1 P1** | `save()` 的"读指纹 → 比较 → 写"不互斥；AI 线程与 UI 线程在**同一进程**并发写 | `base.WRITE_LOCK`（进程内唯一写锁），`save()` 整段持锁；`actions_core` 用**同一把锁** + `load()` 记指纹、`save()` 写前比对（拒绝用旧快照覆盖）|
| **2 P1** | 普通 `git commit` 提交**整个暂存区** → 夹带开发者已 `git add` 的源码 | `git commit --only -- <数据目录>`（只提交这些路径，保留原有暂存状态）|
| **3 P1** | ① 载入后文件损坏 → `save()` 把"读不出来"当"无冲突"直接覆盖；② 留档失败仍写默认值，毁现场 | `_read_disk_state()` 三态（`missing`/`ok`/`unreadable`）：`unreadable` → **拒绝覆盖**；`_quarantine()` 失败返回 `None` → `_write_blocked` 禁止写入 |
| **4 P1** | 撤销整体写回 `before`，会删掉等待期间用户给**别的日期**加的计划 | 记录本次安排**覆盖的日期**（`_arrange_scope`，与快照同口径）→ 只回滚这些天 + 逐日校验冲突；`save()` 被拒 → **保留快照**以便重试 |
| **5 P2** | 迁移失败只保护磁盘：内存停在半成品，之后一次普通保存就写进文件 | 在**深拷贝**上迁移，全部成功才提交；失败回滚内存 |
| **6 P2** | 只挑"存在的路径"会漏掉已跟踪文件的**删除** | 改成目录级 `git add -A -- <数据目录>`：新文件、删除都覆盖，且不再有"路径不存在就 fatal" |
