# 2026-10-18 UI 审查整改 · 第二批（共享组件）

审查材料：`.pytest_cache/ui-audit-20261018/REVIEW.md`（基线 `7881e97`）。
这一批全是**共享组件**——修一次覆盖多页，审查 §6 第 1 条也要求"先修共享组件"。

## U1 · 自绘按钮把所有伪状态解析成 normal（已修）

**问题**：`rounded_button._extract()` 的正则 `QPushButton[^{]*\{([^}]*)\}` 只捕获**声明块**、
把选择器丢掉了，而 `_state(block)` 却在**声明里**找 `:hover` —— 于是四个伪状态全落进
`normal`、后写的规则覆盖先写的（主按钮最后显示的是 disabled 灰、次级按钮长期用 pressed 色）。

**修法**：

| 改动 | 说明 |
|---|---|
| 正则同时捕获**选择器** | `_state_of(selector)` 从选择器读状态 |
| 优先级 | `disabled > pressed > checked > hover`（一个选择器可能同时带多个伪状态） |
| `checked` 分支 | 自绘时原来没有 checked 的取色分支，补上 |
| 缓存失效 | 原来 `_absorbed` 只置一次 → 换主题后自绘底色永远是旧的。现在记住**调用方给的原始 QSS**，`StyleChange` 时作废重算；自己的 `setStyleSheet` 用 `_absorbing` 标记排除，避免自触发循环 |

## U2 · 换主题按"旧色值→新色值"映射丢语义（已修）

**问题**：`_theme_color_map()` 用**颜色值**当键。浅色里 `accent` 与 `accent_text` 可以同色、
深色里却必须不同 —— 于是文字色被换成了填充色（审查实测：浅色 `accent_text` 换成深色填充
`#8F6E33`，应为 `#D9AE58`）。

**修法**：映射**按用途分成两份**（文字色 / 填充色），`remap_colors()` **逐条声明**替换：
`color:` 查文字映射，`background*` / `border*` / `outline*` 查填充映射。
同时把"自绘底色不在 `styleSheet()` 里"这条打通 —— `remap_stylesheets()` 会调用控件自己的
`remap_theme_colors()`（`RoundedButton` 实现它）。

## U4 · 拼接十六进制透明度造成偏色（已修）

**问题**：`background: {bc}18` 这种写法假定 `#RRGGBBAA`，而 Qt 的 QSS 把 8 位十六进制当
**AARRGGBB** —— 所以 `#B93B3B18` 实际是透明橄榄色，不是浅红。

**修法**：新增 `theme.rgba(color, alpha)`（钳制 alpha、输出 `rgba(r, g, b, a)`），
库存面板那 4 处换掉。扫全 `src/ui` 后确认只有这 4 处（审查提到的"习惯和日程也有"已过时）。

## U8 · 代码块对比度（已修）

**问题**：`code_bg` 在浅深两套主题里都是深色 `#3a3a40`，而浅色主题的正文是深字 → 实测
**1.32:1**。

**修法**：给 `code_bg` 配一个成对的 `code_fg`（走 `design/tokens.json` + 生成器 + 同步测试），
`ai_panel._md_to_html()` 用它。顺手把 U3 的另一半也修了：**先 `html.escape` 再做 markdown**，
否则用户正文里的 `<b>` 会被 Qt 当标签渲染。
