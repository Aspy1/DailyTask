# 2026-10-17 Git 同步范围收敛（审查 #4）

## 起因

审查指出两点：① 手动同步用 `git add -A`，会把**开发中的源码**一起提交；
② commit 因"没有改动"失败时 Worker 直接 `return`，**后面的 push 不执行**，上层却显示完成。

动手前先查清了三个前置问题（用户要求）。

## 一、到底同步什么

`git ls-files data/` 原本 **15 个**，其中真正该进库的只有 12 个：

| 类别 | 文件 | 处置 |
|---|---|---|
| 用户数据 | `daily_logs` `expenses` `habits` `inventory` `semesters.json` + `semesters/*/{courses,tasks,exams}.json` | 同步 ✓ |
| 派生 / 缓存 | `weather_cache.json` `weather_stats.json` `search_index.json` | **取消跟踪** + `.gitignore`（项目自己的测试早就把它们叫 "derived"，见 `tests/test_data_schema.py:67`）|
| 已废弃 | `scenes_meta.json`（场景功能已删，只剩一次性迁移输入）· `data/archives/`（空目录） | 取消跟踪 + `.gitignore` |
| 绝不能进库 | `settings.ini` · `app.log` · `backup/` · `schedule_snapshot.txt` | 已在 `.gitignore` ✓ |

远端是**私有仓库**（`Aspy1/DailyTask`, `isPrivate: true`）—— 个人数据没有公开风险。

## 二、结构是否便于统一管理

**保持单仓库**（不拆源码/数据两个仓）：拆开要两套远端与凭据，还会丢掉
"schema 改动与代码改动一起落地"这个真实好处 —— 这个项目改过好几次数据布局
（按学期分文件、场景弃用），那些都是代码 + 数据一起提交的。

但"什么算用户数据"原本是**隐式**的（自动同步一个 glob、手动同步另一套 `-A`）—— 这正是 #4 的病根。
现在收敛为**唯一清单**：`git_sync.DATA_FILES` / `DATA_DIRS`，两条路径共用。

## 变更清单

| 文件 | 改动 |
|---|---|
| `src/services/git_sync.py` | `DATA_FILES`/`DATA_DIRS` 唯一清单；`build_sync_commands()`（`git add -A -- <路径>`）；`is_nothing_to_commit()` / `is_up_to_date()` / `classify_sync()` 三个纯函数；Worker 遇"没东西可提交"**继续执行 push**；`_on_done` 三态；`_data_rel()` |
| `src/app.py` | 托盘状态判断 `status == "done"` → `startswith("done")`（三态带后缀）|
| `.gitignore` | 补 `*.tmp` · `data/app.log*` · `data/archives/` · 四个派生文件 |
| `tests/test_git_sync_scope.py`（新） | 清单必须覆盖 `DataManager._models()`（**防漂移**）· `git add` 必须限定 `data/` 下且用 `--` · push 留在最后 · 三态纯函数 |
| `data/`（取消跟踪 4 个） | `git rm --cached`：跟踪数 **15 → 11**，本地文件全部保留 |

**三态**：`done: pushed`（推送了提交，可能是本次的也可能是之前攒下的）·
`done: up-to-date`（本来就没有待推送）· `error: …`（push 失败，附原因）。
