# 2026-11-03 `ai_undo` 注解导入崩溃

## 症状

启动 `python .\main.py` 在导入阶段崩溃：

```
File "src/services/ai_undo.py", line 174, in SnapshotStore
    def _write_index(self, items: list[Snapshot]) -> None:
TypeError: 'function' object is not subscriptable
```

## 根因

`SnapshotStore` 里有一个方法叫 `list`。在**立即求值注解**的 Python 版本（3.12/3.13，
以及部分 3.14 构建）里，类体执行到 `_write_index` 时，注解表达式 `list[Snapshot]`
中的 `list` 解析成上一步刚定义的同名方法（函数对象），不是内建 `list`，于是
`function[...]` 抛 `TypeError`。

当前开发机的 3.14.9 使用延迟注解，导入不会触发，因此单测全绿仍可能掩盖用户环境的
启动失败。

## 修复

在模块 docstring 之后加：

```python
from __future__ import annotations
```

让全部注解延迟为字符串，彻底规避类体里的同名遮蔽；同时移除两处已无必要的引号
（ruff `UP037`）。

## 验证

- `APP_IMPORT_OK`（`python -c "import src.app"`）
- `pytest tests/test_ai_undo.py tests/test_ai_guard.py tests/test_ai_policy.py`：58 passed
- 全量 `pytest -q`：**1090 passed**
- `ruff check src/services/ai_undo.py tests/test_ai_undo.py`：通过

## 回归测试

`tests/test_ai_undo.py::test_annotations_are_deferred_for_eager_python`
守护未来注解导入存在；注释写明了 `list` 遮蔽的具体触发链。

## 影响

- 运行行为不变；`Snapshot` dataclass 的字段类型仍是字符串注解，dataclasses 不需要解析。
- 项目未使用 `typing.get_type_hints(Snapshot)`，无额外兼容风险。
