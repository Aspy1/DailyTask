# 2026-11-03 `ai_undo` 注解导入崩溃

## 症状

启动 `python .\main.py` 在导入阶段崩溃：

```
File "src/services/ai_undo.py", line 174, in SnapshotStore
    def _write_index(self, items: list[Snapshot]) -> None:
TypeError: 'function' object is not subscriptable
```

## 根因

`SnapshotStore` 里有一个方法叫 `list`。在**立即求值注解**的 Python 版本（3.12/3.13，
以及部分 3.14 构建）里，类体执行到 `_write_index` 时，注解表达式 `list[Snapshot]`
中的 `list` 解析成上一步刚定义的同名方法（函数对象），不是内建 `list`，于是
`function[...]` 抛 `TypeError`。

当前开发机的 3.14.9 使用延迟注解，导入不会触发，因此单测全绿仍可能掩盖用户环境的
启动失败。

## 修复

两层改动（缺一不可，原因见下）：

1. 模块 docstring 之后加 `from __future__ import annotations`：全部注解延迟为字符串，
   规避类体里的同名遮蔽；同时移除两处已无必要的引号（ruff `UP037`）。
2. 把 `SnapshotStore.list()` 移到最后一个使用 `list[Snapshot]` 注解的方法
   （`_apply_undo`）之后：类体顺序不再让 `list` 抢先绑定。方法名、签名、实现和
   调用方全部不变。

为什么两层都要：

- 3.12/3.13 在类体里**立即求值**注解 → 只调顺序即可，只延迟注解也可。
- 3.14（PEP 649）注解**按需求值**，且注解作用域能看到**整个**类命名空间 → 顺序无效，
  必须延迟注解；否则 `typing.get_type_hints(...)` 仍抛同一个 TypeError（本机实测）。

## 影响

- 运行行为不变；`Snapshot` dataclass 的字段类型仍是字符串注解，dataclasses 不需要解析。
- 产品代码不调用 `typing.get_type_hints(Snapshot)`；只有回归测试会解析 `SnapshotStore`
  的方法注解，且延迟注解下这些注解可正常解析（已验证，无额外兼容风险）。
