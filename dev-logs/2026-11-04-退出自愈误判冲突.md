# 2026-11-04 退出时启动自愈被误判为外部修改（ISSUE-0007）

**关联**：`ERRORS.md #061`（同类入口见 `#053`）· `#062`（委派测试管道隔离）·
`MD-files/ARCHITECTURE.md` §7 不变量 2

## 现象

打开应用、不做任何操作直接退出，连续弹出两个"数据保存冲突"；日志：

```
WARNING 退出时 expenses 与磁盘不一致，已跳过覆盖（我方版本存 .../save_conflict/expenses.*.json）
WARNING 退出时 inventory 与磁盘不一致，已跳过覆盖（我方版本存 .../save_conflict/inventory.*.json）
```

每次退出都新增冲突副本，且下次启动→退出重复出现。

## 根因

`DataManager.flush_on_exit()` 自己用"磁盘 JSON == 内存 dict"做冲突判断（第二套实现），
没有使用 `BaseJsonModel.load()` 记下的 `_disk_fingerprint`。启动自愈只改内存、不落盘：

- `ExpenseModel.__init__()` → `_ensure_billing_category()` 补「订阅/分期」分类；
- `InventoryModel.load()` → 补 `item_seq`、旧分类改名、按当前日期重算日期驱动状态；
- `StudyModel.__init__()` → 补默认科目 / `target_date`；
- 空数据目录（新装）也会因 `DEFAULT_STUDY["target_date"]` 为空串而补成日期。

因此"内存与磁盘不同"完全可能只是自愈，却被判成外部写入。

## 门禁修复：委派 E2E 与真实应用抢命名管道（#062）

上一轮全量唯一失败是 `tests/test_delegation.py::test_delegate_end_to_end_assembles_fragmented_reply`
（`CLI 没连上来`）。排查确认不是产品缺陷，而是**测试隔离缺陷**：

- 本机有真实应用进程（`python.exe`）占着 `StudentSchedulerSingleInstance` 管道；
- Windows 上两个 `QLocalServer` 可以同时 `listen` 同名管道，客户端连接会被**真实应用**接走；
- 测试服务端因此永远等不到连接，而 CLI 拿到真实应用的回复后正常退出。
- 关掉应用就通过 —— 旧 dev-log 记录的"预存在失败"正是这个原因。

修复（仍保留原测试强度）：

1. `SINGLE_INSTANCE_KEY` 支持环境变量覆盖（默认值完全不变）；
2. 测试生成唯一 key，用同一个环境变量传给 CLI 子进程；
3. 子进程再加 `LIFE_ASSISTANT_DATA_DIR=tmp_path`，连只读 `status` 也不再碰真实数据。

先红后绿证据：

```
# 只改测试、未加环境变量覆盖时（子进程仍连生产 key）
pytest tests/test_delegation.py::test_delegate_end_to_end_assembles_fragmented_reply
1 failed — AssertionError: CLI 没连上来

# 加环境变量覆盖后
pytest tests/test_delegation.py
16 passed
```

## 行为说明与边界

- **自愈会落盘**：无操作退出时，若内存确有补齐字段且无外部改动，会安全写回（`mtime` 变化）。
  这是推荐路径；未变化的文件不重写。
- **真实外部改动**：磁盘指纹与基线不一致 → 不覆盖，外部内容原样保留，我方版本写入
  `data/backup/save_conflict/` 并发 `save_conflict`（离屏 E2E 用 `QMessageBox.warning` 计数为 0
  验证无操作场景；真实改动用例验证副本与保留行为）。
- **损坏 / 不可读文件**：继续拒绝覆盖，现场保留并产生冲突副本。
- **无磁盘基线**（`_disk_fingerprint is None`）且文件存在：fail-closed，按冲突处理。
- **未做**：`_restart()` 连续两次 `flush_on_exit()` 的重复提示（非目标，另开 issue）；
  不清理既有冲突副本；不改 schema / UI / 依赖 / 真实 `data/`。

## 数据安全
