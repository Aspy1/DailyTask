## 问题与修复

### 1. worker 线程直接改 Model（`Q-B2`，最高风险）
`InstructionParser.execute(commands, dm, settings)` 在 **AI worker 线程**里执行
`dm.reload_all()` + `dm.data_changed.emit("ai_action")`，与主线程的
`DataManager._auto_reload`（3s 轮询）和 UI 刷新**同时读写同一批 dict**。

**修复**：`execute(commands)` 只负责跑命令；重载与通知移到**主线程**的
`AIService._on_response_with_instructions`（该槽由信号队列投递到主线程）。

### 2. 类级可变缓存（`RUF012` ×5）
`AIService._ds_balance_cache` / `_weather_cache` 是**类属性**（跨实例、跨线程共享）。
`I18nLoader._strings` 同理。`TaskModel.GENERIC_TAGS` / `InventoryPanel.CATEGORY_LABELS`
是**真常量**，误报为可变状态。

**修复**：前两者改为实例属性（`__init__` / `__new__` 中初始化）；后两者标注 `ClassVar`。
`ruff --select RUF012` 现为 0。

### 3. 分层违规（`Q-A2`）
`api_service.py` 从 `src.ui.styles.theme` 导入 `get_colors`，但**从未使用**。

**修复**：删除该死导入 → 服务层不再反向依赖 UI，`F401` 与 `Q-A2` 一并消除。

### 4. `QThread.terminate()`（`Q-B3`）
`api_service._run_worker` 直接强杀线程。

**修复**：不终止旧线程；新请求覆盖 `_current_worker`，回调按 `sender()` 判断并**丢弃过期结果**；
worker 结束即 `deleteLater`。

### 5. QThread 生命周期（`Q-B5`）+ **真实 bug**
`weather_service` 共用一个 `self._worker` 槽。后果不只是泄漏——
`start_auto_update()` 里 `_fetch_now()` 后紧跟 `_fetch_7d()`，后者被
`if self._worker.isRunning(): return` 挡掉 → **7 天预报永不刷新**。

**修复**：改为 `self._workers: dict[api_type, worker]`，按类型独立、同类型不并发、结束即回收。

### 6. stdout 全局重定向（`Q-B4`）
`actions.run_in_process` 用 `contextlib.redirect_stdout`（`sys.stdout` 是进程级全局），
多线程并发执行会互相污染。

**修复**：模块级 `threading.Lock` 串行化。
> 彻底方案（待办）：把 handler 从 `print(...)` 改为 `return str`，不再重定向 stdout。

### 7. CWD 相对路径（`Q-E2` 同源问题）
`weather_service` 与 `settings_panel` 用 `Path("data/...")` 读写天气缓存/统计。
应用可能由**自启**拉起（CWD 非项目根，Windows 下甚至可能是 `C:\Windows\System32`）→ 写错位置。

**修复**：改为基于 `__file__` 的绝对路径。

## 教训

- **"共用一个 worker 槽"不只是资源问题，会直接导致功能静默失效**（7 天预报从未刷新）——
  线程/资源管理 bug 常以"功能不生效"而非"报错"的形式出现。
- 类属性做缓存 = 全局可变状态，即使单实例也经不起线程与测试的双重考验。
- 跨线程改数据的最优解通常**不是加锁，而是把写操作收敛到单一线程**（此处即主线程）。
