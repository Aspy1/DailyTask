## 做法

**不是**重写，而是**按语义抽取辅助函数**（约 40 个新 helper），例如：

- `ScheduleView`：`_refresh` 拆出 `_slot_for_minutes` / `_current_slot` / `_build_slot_data` / `_build_ddl_by_slot` / `_content_hash` / `_create_slot_card` / `_create_course_item` / `_create_plan_item` / `_create_habit_item` / `_create_ddl_label`
- `send_digest.build_digest`：拆成 `_digest_summary/_courses/_plans/_habits/_urgent/_exams/_balance/_expenses/_shopping` 九个分区函数
- `actions.py`：`match_course` 拆出 4 级匹配策略；`parse_date`/`normalize_time` 拆出各中文日期/时间分支
- `reminder_service`：`_check` 拆出习惯批、DDL 邮件、考试、自定义提醒四条独立链路

## 验证方式（这次做得比较硬）

1. **运行期冒烟**：离屏构建真实 `QApplication` + `DataManager` + 控件，跑 `_refresh()` / `_build_snapshot()`。
2. **差分等价性对比**：并发加载 HEAD 版本与当前版本，逐一比对可观测输出——脚本/服务层比对
   `actions` 全部命令的真实读写结果、系统提示词全文、天气 7 条分支等（28,687 + 20 项，0 差异）；
   UI 层比对控件树的 `objectName` + `styleSheet`、表格 item 与 cellWidget、多种筛选/高亮路径（全部一致）。
   > 这一步抓出了一处真实保真问题：抽取 `_HabitCard` 按钮 QSS 时丢了原有的缩进，被比对发现并还原为**原始字节**。
3. 常规四道门：compileall / ruff / pytest / 令牌检查器。

## 修掉的两个真实 bug

1. **`TaskPanel._refresh` 崩溃（用户可触发）**：`c = get_colors()` 只在「DDL 临期」分支里赋值，
   却在「已完成」标题分支被读 → 把筛选切到**已完成/全部**且存在已完成任务时抛
   `UnboundLocalError`。已在 HEAD 上复现确认为**既有 bug**，本次修复，并补 4 条回归测试
   （`tests/test_task_panel.py`，新增离屏 `qapp` fixture）。
2. **命名遮蔽**：重构 `_build_system_prompt` 时新增的 helper 一度命名为 `_prompt_cache_key`，
   与既有缓存属性**同名**，会把方法覆盖成 tuple → 第二次构建提示词必 `TypeError`。
   由差分对比发现后改名为 `_compute_prompt_cache_key`。

## 教训

- **复杂度重构的验收标准是"等价"，不是"看起来对"**。差分对比（HEAD vs 当前）成本不高，但能一次性
  覆盖几十条执行路径；在本项目 1% 覆盖率的现实下，它比补测试更快见效。
- **"行为完全不变"也可能保留 bug**。`TaskPanel` 那个崩溃是既有 bug，重构 agent 按指令原样保留并**显式上报**——
  这是正确做法：先记录、再单独修，而不是夹在重构里悄悄改。
- 抽取函数时，**字符串字面量的缩进也是内容**（QSS 的多行字符串缩进会进样式表）。
