# 2026-10-17 · 课表导入时段整体偏移：修正 + 补 update_course

## 用户报告

> 导入后时间整体向下推移了一节课；让 AI 修正，它回复了奇怪的代码
> （`python scripts/actions.py status 2>&1 | head -50; echo ---; ls scripts`）。

## 根因一：小节 vs 大节（15 门课时段错位）

用户课表按**小节**排（一天 8 小节：第一节 08:30-09:15、第三节 10:25-11:10…），
而本应用一天只有 **6 个大节**，每个大节含两小节（大节 1 = 08:30-10:05 = 小节 1+2）。
AI 把"第几节"**1:1** 当成了 slots：

| 课表 | AI 写成 | 应用显示 | 正确 |
|---|---|---|---|
| 第一节 | slots 1 | 08:30-10:05 | ✓ 对 |
| 第三节 (10:25) | slots **3** | **13:30-15:05** ✗ | slots 2 |
| 第五节 (13:30) | slots **5** | **18:30-20:05** ✗ | slots 3 |
| 第七节 | slots 4 | 15:25-17:00 | ✓ 对（碰巧） |

**修正**：用新命令 `update_course` 逐门改 `--slots`（15 门：10 门 3→2、5 门 5→3），
分布从 `{1:8, 3:10, 4:6, 5:5}` 变成 `{1:8, 2:10, 3:5, 4:6}` —— 与用户课表结构一致。

**防复发**：提示词里加"小节 → 大节"对照表 + `大节 = ceil(小节/2)`，
并说明"同时给了时间就用时间判断落在大节几"。

## 根因二：没有"改课程"命令 + 模型写了 shell 管道

- 命令集里只有 `add_course` / `delete_course` ✗ → AI 想修正时段**没有可用的命令**
  （只能删了重建，会丢 id 和别的字段），于是它去跑 `status` 看状态；
- 它写的还是 `... status 2>&1 | head -50; echo ---; ls scripts` —— 带管道/分号/echo/ls；
- 而 `parse` **只认 ```sh 围栏**，模型写的若是 ```bash 则命令**根本不执行**，
  同时"剥代码块"的正则也只处理 sh/json → 代码就**漏到聊天里**给用户看了。

**修复**：
1. 新增 **`update_course`**（只改显式传入的字段：name/day/weeks/slots/parity/location/teacher）；
2. `parse` 接受 ```sh/```bash/```shell/```console/```zsh；显示侧统一走 `_strip_code_blocks()`；
3. 提示词明确"**不要**写 `|`、`;`、`&&`、`echo`、`ls`、`head`、`2>&1`"；
4. 提示词写明"修正已导入课程用 `update_course`，不要删了重建"。

## 顺手抓到的既有隐患（`ERRORS #046`）

`_build_action_namespace` 会给**所有**命令注入 argparse 默认值 → `update_*` 语义是
"只改传入的字段"，于是：

- `update_item --id i_001 --location "柜子"` 会把 **quantity 重置成默认的 1**；
- （新加的 `update_course --slots` 也会把 parity 重置成 all —— 写完立刻被这个坑绊到）。

修：`update_*` **不注入默认值** + 相关 handler 全部改 `getattr(args, x, None)`
（旧实现直接 `args.quantity`，属性不存在就 `AttributeError`，日志里那条
`ERROR 'Namespace' object has no attribute 'unit'` 正是同一来源）。

## 我自己的一个失误

修完后我顺手跑了一条"验证"命令 `update_course --id c_001 --slots 2-2` ——
但 `c_001`（自然语言处理 周一）**本来就在第 1 节**（正确），我把它改错了 ✗。
已立刻改回 `--slots 1-1` 并核对分布恢复 `{1:8, 2:10, 3:5, 4:6}`。
教训：**验证也应该只读**；写操作必须先确认目标当前值。
