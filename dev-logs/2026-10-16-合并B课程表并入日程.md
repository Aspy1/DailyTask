# 2026-10-16 · 合并 B：课程表并入日程（日/周 切换）

## 起因

用户拍板"方案 B"：**删掉独立的「课程表」导航项，并入「日程」+ 顶部 日/周 切换**。
动机：课程表和日程总览本就是"同一件事的两个视角"，分成两个导航项后，
用户要在两处之间来回切；而且**周视图只有课程块** —— 没课的日子一片空白，
看着像"这周什么都没有"（实际有作业截止、考试、日程计划）。

## 变更清单

1. **导航**：侧边栏「课程表」移除；「日程」文案由"日程总览"改为**"日程"**。
2. **日/周 切换**：`ScheduleView` 顶栏加两个小按钮（激活态用强调色 token，
   不写死颜色）；`_set_mode()` 切 `QStackedWidget` 的第 0/1 页。
   切到周视图时隐藏日视图专属控件（日期导航 3 个 / 调整按钮 / 外层刷新），
   避免"两个工具栏各一个刷新"的重复感。
3. **周视图**：内嵌 `CoursePanel`（复用其周导航与课程数），
   并在课程表**末行**列出当天事项 —— 这是本轮的关键点：
   | 类型 | 文案 |
   |---|---|
   | 作业截止 | `截止 · {作业标题}` |
   | 考试 | `考试 · {课程名}` |
   | 日程计划 | `计划 · {标题}` |
   事项行按内容自适应高度；**整周都没有事项时整行隐藏**（不留一条空白带）。
4. **工作区**：`courses` 不再是独立面板；`MainWorkspace.course_panel` 保留为**委托属性**
   （`CourseDetailDialog` 入口与既有测试不用改）。
5. **令牌**：`course_color_1..8` 早已无人引用（课程块改中性色后遗留）→ 删除，
   并清掉两个脚本里的过期前缀；`gen_design_tokens.py` 重新生成规格表，同步测试通过。

## 决策原因

- **为什么把课程表做成"日程的一页"而不是并排**：两者共用同一批数据（课程 / 计划 / DDL / 考试），
  并排会让"今天有什么"这个最常见的问题需要看两处；做成日/周切换后，**同一屏回答同一个问题**。
- **为什么事项行放在表格末行而不是塞进课程块**：课程块代表"这节课"，把作业/考试混进块里会
  让块语义变脏；独立一行既保留"课程 = 时间占用"的语义，又能一眼看到"这周有哪些非课程的事"。
- **为什么保留 `course_panel` 委托属性**：外部（菜单、测试）把它当"课程表入口"用，
  属性委托让接口不变、内部结构可自由调整。
