# 2026-10-18 库存归属：位置就是归属（学校 / 家）

用户需求：换季时会把部分衣物**邮寄回家**、来年再寄回，所以「有什么」要能表达"在哪一边"，
并且能切换查看；家那份**不区分位置**。

**这个功能做了两版，第一版被用户否掉。** 两版都记在这里 —— 否掉的理由比最终实现更值得留。

## 第一版（已废）：数据集字段 + 让模型判断"家里"指哪边

做法：物品加 `dataset`（`local`/`home`），顶层加 `current_dataset`（界面与命令行读同一份，
照 `semesters.json` 的 `current_semester`）；`--dataset` 用在增/改/查；家那侧不使用位置。

**为什么被否**（用户原话）：*"这么区分家 和家里绝对会有问题，flash 模型本来处理中文就不咋地"*。

- **"家"这个标签与日常说的"家里"撞车**：用户说"**家里**抽纸还有 3 提"通常指**手边**，
  而模型可能理解成"寄回家的那批"。
- 这不是理论担忧，是**实测**：探针样例 1 里模型发出了
  `add_item … --dataset home`（本该记在本地），位置被规则拒掉后又重试成一条**不带位置**的记录。
- 我当时的"修法"是给提示词打补丁（"`--dataset home` 只用于明确要寄回/收起来"）——
  **本质还是让模型去理解中文意图**，只是换了个说法，迟早再错。

**结论**：把"归属"交给模型判断是错的方向。要么让它判断的东西变成**字符串抄写**，
要么就别让它判断。

## 第二版（现行）：位置单轴

用户口径：*"归属地问题这样：我明确说位置，不说位置默认场景为学校。"*

- **位置是唯一的归属信号**：说了位置就用它；没说 → **默认「学校」**。
- **归属由位置推导，不单独存字段**：
  - 位置是「家」→ **家侧**（`HOME_LOCATIONS`）
  - 其余位置（宿舍格位 / 「学校」/ 空 / 后来新增的）→ **学校侧**
  - 规则只有一处：`InventoryModel.side_of()`
- 词表 `locations[]` = 宿舍格位 + **「学校」「家」**两个粗格位（`set_locations` 维护）。
- 模型要做的只剩两件**机械**事：①用户说了位置就**照抄**；②没说位置就写常量 `学校`。

**默认值的两个细节**：

1. 虚拟品类（会员之类）**不吃**"学校"这个默认 —— 对它们没意义，留空更诚实。
2. 默认值是**常量**，**不依赖界面状态** —— 所以命令行不需要知道"用户正在看哪边"，
   也就不会出现"看着家那侧改了一条学校物品"这种误判。

**界面切换是纯视图状态**（`InventoryPanel._side`）：不写数据文件、不进 git 同步。
这顺带解决了第一版的一个副作用（第一版把 `current_dataset` 写进数据文件 → 每切一次视图
就产生一次同步提交）。

## 门禁逼出来的抽离（两版共用，保留）

`check_quality` 的 SIZE 是"**只防新增**"：`InventoryPanel` 类基线 729 行、`__init__` 基线 120 行、
`inventory_panel.py` 原本 ≤800 —— 加功能把它们**加重**了，于是必须**抽离存量代码**抵消：

| 动作 | 效果 |
|---|---|
| 两个对话框（改标签 / 设邮件提醒）→ 新模块 `src/ui/panels/inventory_dialogs.py` | 面板 −88 行（743 行 ✓）、类 −88 行 |
| 面包屑整块 → `_build_breadcrumb()` | `__init__` 127 → 89 ✓ |
| `edit_tags_dialog` 的"新标签输入行" → `_tag_input_row()` | 64 → 50 ✓ |
| `_render_item_card` 的 parts 收集改成一行推导式 | 61 → 57 ✓ |
| `actions_cli._add_item_parsers` 把多行 help/注释并成一行（`E501` 是关的） | 65 → 59 ✓ |
| `_item_line` 拆出 `_item_extra()` | RADON 从 C(11) 降下来 |

**教训**：给这个项目加界面功能，几乎必然要先抽离存量 —— 面板/类的尺寸上限早就贴边了。
`actions_core.py` 现在 797 行、`inventory_panel.py` 758 行，都还在 800 附近，下次动它们要提前算。
