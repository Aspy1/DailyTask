# 2026-10-19 学期检查提示点名课程

## 起因

全量验收（`acceptance_check.py`，79/79 ✓）里那条提示：

```
[OK] 对话框检测结果有内容 — 数据检查
· 有课程的周次范围超出学期
```

**问题不是"报错了"，而是"报了也没法动手"** ✗ —— 用户有 20 多门课，
提示只说"有课程"，不说**是哪门**。用户得自己一格格翻课表找 ✗。

## 成因

`models/semester.py` 的检查是**问题码**（`ISSUE_COURSE_WEEKS` 等字符串），
设计上就是机器可读、便于去重 ✓ —— 但 UI 直接 `tr(f"semester.issue.{code}")` 渲染，
**信息在"码 → 文案"这一步丢掉了对象**（哪门课）。

## 改法

1. `models/semester.py` 新增 **`courses_out_of_week_range(courses, total_weeks) -> list[str]`**
   —— 返回超范围课程的**名字**（没有 `name` 就退到 `id`）。
   ⚠ 判定**复用 `_weeks_out_of_range`**，不另写一套（两处口径必须同源 ✓，
   测试里用 `validate_courses(...).count(ISSUE_COURSE_WEEKS)` 对照断言 ✓）。
2. `ui/widgets/semester_dialog.py`：`_render_issues(report)` → `_render_issues(report, status)`，
   新增 `_issue_detail(code, status)` —— **只对 `ISSUE_COURSE_WEEKS` 这条**补
   `（高数、英语，共 2 门）`；超过 3 门只列前 3 个 + `…`。
   为什么只做这一条：它是本项目里**唯一"有多个可能对象、必须点名"**的检查 ✓
   （其它问题码指向的东西是唯一的：学期本身）。
3. 新 i18n 键 `dialog.semester.issue_course_weeks_detail`（文字只进 JSON ✓ `Q-N5`）。

## 验证

- 新增 2 条测试：`tests/test_semester.py::test_courses_out_of_week_range_names_the_courses`
  （含"与 `validate_courses` 同源"断言）、
  `tests/test_semester_ui.py::test_dialog_issue_line_names_courses_out_of_week_range`
  （**真的建一门超范围课，断言对话框文字里有课名** ✓）。
- **638 passed**（636 + 2 ✓）；`ruff` / `check_ui_tokens --strict` / `check_quality --strict` 全绿（退出码 0 ✓）。

## 教训

**"检测到问题" ≠ "用户能解决"** ✓ —— 机器可读的问题码适合内部传递，
但**用户出口必须带定位信息**（哪个对象、在哪儿）✓。以后新增检查项时先问一句：
"用户看到这条提示，下一步知道点哪儿吗？"
