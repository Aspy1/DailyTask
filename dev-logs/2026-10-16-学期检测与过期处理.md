# 2026-10-16 · 学期合法性检测 + 学期过期处理

## 起因

用户要求做「学期数据合法性检测」与「学期过期功能」。触发点是真实数据里学期
`start_date` 过旧，状态栏显示 **"第 32 / 16 周"**（第 32 周根本不存在）。

排查后确认：这不是"某个算式写错"，而是**同一件事在 5 处各算一遍、口径不同** ——
所以本轮的重点是**收成单一真值**，再在其上做检测与过期处理。

## 变更清单

### 1. 单一真值：`models/semester.py`

| 函数 | 口径 |
|---|---|
| `semester_status(sem, today)` | **显示用**：`state` ∈ none/invalid/not_started/active/expired；`expired` 时 `week` 钳到总周数 |
| `week_number_for(sem, target)` | **取课表用**：超范围返回 `None`（不钳制） |
| `validate_semester` / `validate_courses` / `validate_all` | **检测用**：返回问题码 |

改用它之后，5 处各算一遍的历史结束：

| 位置 | 旧 | 新 |
|---|---|---|

| `send_digest` | 第三套算法 | 同一份实现（纯函数，脚本仍无 Qt 依赖） |

### 2. 合法性检测（14 个问题码）

- **学期级**：缺 id / 缺开始日期 / 无法解析 / 超出 2000–2100 / 缺总周数 / 总周数不在 1–30 / 节次不在 1–12
- **模型级**：`current_semester` 指向不存在 / 有课程却没学期 / id 重复 / 学期区间重叠
- **课程级**：周次超出学期 / 星期不在 1–7 / 节次无效（空、起止颠倒、超上限）

问题码是机器可读的，文案在 `ui/components/semester_text.py`（`Q-N5`：模型层不产用户文案）。

### 3. 安全自愈（幂等）

只补**能安全推断**的：`id`、`total_weeks=20`、`period_count=5`；
`current_semester` 失效时挑最合理的（今天落在其区间内 > 开始日最新）。
**不猜 `start_date`** —— 猜不出就报出来让用户改，避免"自愈"把数据改坏。

### 4. 过期处理（UI）

- 状态栏：`学期已结束`（强调色，可点击 → 学期管理）
- 课程表：`学期已结束 · 第 20 / 20 周`（状态与"正在看第几周"两件事都说清）
- **学期管理对话框**：状态 + 起止日期 + 检测结果；切换当前学期；新建学期（默认开始日 = 下一个周一）

### 5. 顺带修掉的两个坑

- **`ERRORS #036`（区域 CJK 数字）**：本机 `zh_HK` 区域在 CLDR 里用 CJK 数字，
  `QDateEdit`/`QSpinBox` 把 `2026-10-19` 显示成 `〢〇〢〦-〡〇-〡〩`。
  项目里原本有两处**给单个控件**打补丁（`inventory_panel` / `schedule_view`），
  新控件（`habit_panel` 的 QSpinBox、本轮 `semester_dialog` 的 QDateEdit）又中招 →
  改为 `theme.configure_locale()`，由 **`init_theme()`** 统一调用（任何 UI 入口都覆盖），
  守卫 `tests/test_locale.py`。
- 删除 `CourseModel.active_courses`：**无人调用的死代码**（`Q-A4`；vulture 不查 property，
  是人工核对发现的）。

## 决策原因

- **为什么把纯逻辑抽成 `models/semester.py` 而不是写在 `CourseModel` 里**：
  邮件摘要在 GitHub Actions 里跑、**不能依赖 Qt**，但它必须和桌面端口径一致。
  纯函数模块两边都能用，这才可能"只有一份实现"。
- **为什么分"显示口径"与"取课表口径"两个函数**：显示需要把已结束钳到总周数
  （否则又出现 32/16），而取课表必须知道"这一天根本不在学期内"（返回 None），
  两者的正确行为不同，不能用一个函数硬凑。
- **为什么自愈不猜 `start_date`**：开始日期无法从任何现有数据推断；
  猜错会让整学期课表错位，比"报出来让用户填"危险得多。
- **为什么区域修复放在 `init_theme()`**：这是所有 UI 入口的必经之路；
  放在 `App.__init__` 只覆盖主程序（我自己写截图脚本时就漏了，暴露了这个问题）。
