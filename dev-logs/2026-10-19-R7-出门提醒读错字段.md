# 2026-10-19 R7：出门提醒读了不存在的字段（批次二收尾）

## 起因

`PLAN.md` P22 批次二最后一条（`REVIEW.md` R7）。

`hints._has_class_on()` 这样判断"今天有没有课"：

```python
days = [int(s.get("day", 0)) for course in courses for s in (course.get("time_slots") or [])]
return weekday in days          # ✗ `time_slots[].day` 生产里不存在
```

生产课程的**星期在 `course.day_of_week`** ✓，slot 只记节次和地点（`start` / `end` / `location`）✗
—— 所以 `days` 永远是 `[0, 0, …]`，"今天有课"**永远为假** ✗：只有"今天有安排"才会提醒出门，
**真实上课不触发** ✗。

更糟的是**测试配合了实现** ✗：旧测试专门造 `{"time_slots": [{"day": 1, "start": 1}]}`
这种生产造不出来的形状 → 全绿，却什么也没证明。

## 改法

按审查建议：**不另写简化课程日历，复用生产的 `CourseModel.get_courses_for_date()`** ✓
（它已经处理教学周 / 单双周 / 节假日 / 调课 / 未开学 / 期末周 ✓）。

- `_courses_today(data_dir, today)` 改成用 `SemesterRegistry` + `CourseModel` 调
  `get_courses_for_date(today)` ✓；读不到（学期缺失 / 文件损坏）→ 返回空列表，
  **少一条提示、不影响别的功能** ✓（提示本来就是锦上添花）。
- `_has_class_on()` **删掉** ✓；`_outing_reason()` 改成 `if courses:` —— 传进来的就是
  "今天该上的课" ✓，这里**不再自己按星期几筛**（那需要猜字段名，R7 就是这么错的 ✗）。
