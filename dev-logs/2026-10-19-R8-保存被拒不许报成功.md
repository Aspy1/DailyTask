# 2026-10-19 R8：保存被拒时不许报成功（批次一收尾）

## 起因

`PLAN.md` P22 批次一最后一条（`REVIEW.md` R8）。

`edit_membership_dialog` / `edit_tags_dialog` 调 `dm.*.save()` 却**不看返回值** ✗：

```python
dm.inventory.update_item(item["id"], {"membership": membership})
dm.inventory.save()                       # ✗ 返回值没人看
dm.membership_contacts.set_phone(...)
dm.membership_contacts.save()             # ✗ 同上
return True                               # ✗ 一律报成功
```

磁盘被别人改过时保存会被**冲突检测拒掉**，但弹窗照常关闭、调用方照常发数据变化信号 →
**用户看到内存里的新值，磁盘上没有** ✗。

> 同一个文件里的 `email_reminder_dialog` 早就是正确写法（检查返回值 + 告警 ✓，
> 那是上一轮审查 F4/P2 修的）—— 这里把它**推广**到另外两个弹窗 ✓。

## 改法

| 位置 | 行为 |
|---|---|
| 标签弹窗 | `save()` 被拒 → 告警 + 返回 `False`（不报成功） |
| 会员弹窗 · 第一步 | 库存保存被拒 → 告警 + 返回 `False`，**且不再去写私有文件** |
| 会员弹窗 · 第二步 | 私有文件被拒 = **部分成功** → 单独一句"会员信息已保存，但**手机号没写进去**" + 返回 `False` |

新增 4 个 i18n 键（`panel.inventory.msg_save_failed[_title]` /
`msg_phone_save_failed[_title]`）。

## 验证

新增 `tests/test_inventory_dialog_save.py`（**4 条**），用**桩**把保存打回 `False`
（审查要求"补库存冲突 / 私有文件冲突路径"）：

- 库存被拒 → 返回 `False` + 告警 + **没有**去写私有文件；
- 私有文件被拒 → 返回 `False` + 告警文案含"手机号"（部分成功如实说）；
- 两条都成功 → 正常返回 `True`（别把成功也当失败）；
- 标签弹窗被拒 → 返回 `False` + 告警。

**并证明测试不是空的**（`git stash` 回旧源码）：

```
旧代码：3 failed, 1 passed     ← 真的抓得住
新代码：4 passed
```

**664 passed**（660 + 4）；`ruff` / `ui_tokens --strict --check-px` / `check_quality --strict`
全绿（**退出码全 0**）。

## 没做完的部分（如实记，进批次三）

审查还提到"**标签编辑及新增计划完成/分类动作**也应统一检查 save 结果"。

（`task_panel` / `habit_panel` / `expense_panel` / `course_panel` / `settings_panel` /

约定（共用的小助手 + 文案），再分批迁移。R8 只按审查给的位置修了 `inventory_dialogs.py`，
其余留在批次三，**不假装已经解决** ✗。
