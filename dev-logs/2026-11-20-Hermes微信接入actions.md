# Hermes 微信接入 actions

日期：2026-11-20。复杂度：L3（新增跨进程调用、工具提示与多文件行为）。

## 目标与执行链

按用户要求将 Hermes 的 Go 模型改为 `deepseek-v4.1-flash`，让已登录微信机器人
通过项目既有命令入口完成作业、课程与日程事项。保留已有桌面 AI 功能，
本次只增加受控的外部入口；不改业务数据 schema、不引入项目依赖。

链路：微信 → Hermes 插件工具 → JSON stdin 桥接 → ai_guard
→ 项目 venv 启动 actions CLI → 应用委派或原有原子写入 → 回读验收 → 结构化回执。
查询只读当前学期与指定日期数据；部署路径由操作者配置，模型不能传任意路径或命令。

## 原因与决策

原生插件将模型意图与确定性写入隔开，复用现有脚本的参数校验、备份和应用委派；
不安装已归档的直改 JSON skill。CLI 与进程内接收器属于两个解析边界，
必须同时验证应用启动/关闭两种情况。审计脱敏也需按照真正的 argv 边界处理。

保留其余预存工作区改动；提交包含本次文件、共享文件增量及上述必要的隔离/门禁依赖。
插件需重新部署后才能加载更新；运行中的桌面应用需重启以加载委派解析修复。
本次不设置开机自启动。
