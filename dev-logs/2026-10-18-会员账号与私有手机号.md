# 2026-10-18 会员账号与私有手机号

用户需求（正在重建库存时提的）：*"虚拟品类通常为会员，则需要与账号绑定，属性包括手机号、
用户名、到期日期、是否开启自动续费以及自动续费时长。其中手机号选填且不上传至仓库。"*

## 先审查需求（三个提醒）

1. **手机号还有第二个出口**：用户只说了"不上传至仓库"，但手机号若进 `inventory.json`，
   会随每次对话**发给模型服务商**（提示词里带物品清单）。所以按"**两个都不进**"办：
   仓库不进、提示词也不进。配套建议：**手机号只在面板里录，别跟 AI 说**
   （跟它说，那句话本身就已经发出去了）。
2. **存法**：手机号放 `data/private/memberships.json`（按 id 索引）—— `.gitignore` 挡住，
   并登记进 `git_sync.PRIVATE_FILES`（"故意不同步"清单）。用户名 / 到期日 / 自动续费 /
   续费月数进 `inventory.json`（会同步，仓库是私有的）。
3. **正在重建这件事**：这次重建加进去的会员**不会**带账号信息（应用还是旧代码），
   重启后要么在面板里补，要么把那几条重说一遍。

## 用户口径（三个决定）

1. **到期日决定状态**：过期 → 需购（要续费）；7 天内 → 不足（要到期了）；否则充足（有效）。
   面板上"虚拟品类"的标签本来就是 要续费 / 要到期了 / 有效，正好一一对应。
2. **自动续费只是记着**：开着也照常按到期日算（你要知道它什么时候扣钱）。
3. **用户名不算敏感**：放 `inventory.json`（只有手机号私有）。

## 关键设计决定

1. **`effective_status()` 只对会员重算**。会员的状态随时间变（到期日），存下来的 `status`
   是写入那一刻的快照；但**非会员**的 `status` 可能是用户用 `--status` 手动改过的，
   一并重算就会把它覆盖掉。
   → 这是被测试抓出来的：`test_actions_smoke` 里 `update_item --status 需购` 之后，
   我的第一版"到处重算"让 `need_restock` 又把它算回"充足"。现在只有**有到期日的物品**
   才重算，其余一律信存下来的值。
2. **私有文件仍是一个受管模型**（`_models()` 里），只是登记在 `PRIVATE_FILES` 而不是
   `DATA_FILES`。这样 `test_git_sync_scope` 的"每个模型都要有归属"这条不变式还成立，
   而且新增了一条断言：私有清单里的每一项都必须被 `.gitignore` 挡住。
3. **手机号有三道防线**：命令层直接拒绝 `--membership` 里的 `phone` / `手机号`；
   提示词明说不要问、不要写；提示词构造函数只读 `membership`（结构上就没有手机号）。
4. **续费时长存月数**（`renew_months`）—— 只有数值才能算出下次到期日。

## 踩到的坑

1. **`MAX_TEXT = 80` 装不下会员 JSON**：一个带四个字段的 `--membership` 是 82 字 →
   被长度校验拒了（现象是"该成功的那条命令什么都没写"）。新增 `MAX_JSON = 500`，
   顺手把 `--instances`（也是 JSON，原来同样卡 80）一起放宽。
2. **"到处重算状态"是个错误方向**（见上面第 1 条）—— 靠 `test_actions_smoke` 抓出来。
