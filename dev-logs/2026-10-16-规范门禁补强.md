## 变更清单

### 1. 修 5 个"没被检查出"的真缺陷

1. **`habit.py` monthly 分支（Q-C3）**：`logs` 是 `logs[日期][habit_id]` 两层，
   旧代码 `for hid, ts in self.logs.items()` 把**顶层键（日期）当 habit_id** 比较 → 恒 `False`
   → 每月习惯永远判"未达标"（天天出现，配额形同虚设）。
   改为按"本月已完成次数 vs `schedule.value`"判定。
2. **2 处静默吞异常（Q-I2）**：`theme.py` / `check_ui_tokens.py` → `contextlib.suppress(...)`。
   审计同时发现 **ruff `S110` 只拦裸/`Exception` 异常，不拦具名 `except (A, B): pass`**（`ERRORS #033`）。
3. **6 处 `len()+1` 生成 ID（R-008 明禁）**：新增 `models/base.next_id()`，按最大数字后缀 +1；
   保持 `c_001` 格式（`actions.py:45` 的 `int(id.split("_")[1])` 仍可用）。
4. **Q-A1 尺寸**：实测超限 **36 项**（4 文件 / 6 类 / ~26 函数），记入 baseline 防新增。
5. **Q-N5 i18n**：`src/ui` 内 `tr()` 仅 19 处、中文字面量 692 处、`zh-CN.json` 92 个扁平键，
   记入 baseline 防新增（是否全量迁移待裁决）。

### 2. 门禁补强

`scripts/check_quality.py`（`--strict` / `--write-baseline`）检查项：

| 项 | 规则 | 口径 |
|---|---|---|
| `SIZE` | Q-A1 | baseline 防新增 |
| `SILENT` | Q-I2 | **必须 0**（AST，兜住 ruff S110 的漏检） |
| `ID-GEN` | R-008 | **必须 0** |
| `TOKEN-NAME` | Q-H3 | baseline 防新增 |
| `I18N` | Q-N5 | 不得超过 baseline |
| `TOP-DIR` | Q-P1 | 只查 **git 跟踪**的顶层项（本地垃圾不影响 CI） |
| `SECRET` | Q-E1 | `data/settings.ini` 不得被 git 跟踪 |
| `VULTURE` | Q-A4 | 必须无输出 |
| `RADON` | Q-C1 | `cc -n C` 必须无输出 |

设计原则：**能绝对化的必须为 0；有历史债的走 baseline，只防新增**。

## 决策原因（为什么这么做）

- **为什么用 baseline 而不是"一次全修"**：尺寸/i18n/令牌命名三项都是**大改动面**（拆类、692 处
  文本迁移、令牌重命名），一次全做会把"补门禁"和"大重构"绑在一起，风险与时长都失控。
  baseline 让门禁**立刻生效**（挡住新增），同时把存量债显式登记，避免"以为已经达标"。
- **为什么 `TOP-DIR` 只查 git 跟踪项**：白名单约束的是**仓库**，不是本机磁盘；
  本地 `.coverage`、空目录不该让 CI 变红（否则门禁会被绕过或长期挂着红）。
- **为什么归档而不是删除 hermes skill**：它是用户放进来的第三方产物，按 `AGENTS §0`
  不擅自删除；但它的"直接读写 `data/` JSON"与 `R-002` 冲突、还提到 `settings.ini`，
  所以移到 `MD-files/archive/` 并写明冲突点。
