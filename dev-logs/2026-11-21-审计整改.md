## 变更清单

### P0-1 跨学期恢复

- 备份清单（`backup/actions/index.json`）：`backup_id` / 相对目标路径 / `semester_id` /
  `schema_version` / `supported_version` / `sha256` / `created_at` / 单调 `seq`。
- 轮转改按 `seq`，**同秒多份**不再靠文件名排序（原来 `-10` 会排在 `-2` 前面，
  选出的"最近一份"其实是旧的）。
- `restore` 先解析**显式目标**，在目标锁内依次校验 归属 → 版本 → 内容指纹，全部通过才提交。
- 旧快照（清单里没有）来源未知 → 要求 `--semester` 显式声明归属；共享文件（`inventory.json` 等）
  不受学期校验限制。
- 新增 `list_backups --stamp/--semester` 过滤。

### P0-2 撤销绑定实际提交版本

- `actions_core.save()` 在**目标文件锁内**产生回执（操作 ID / 目标 / 提交前后 sha256 /
  版本 / 变更字段），按线程分开存（`scripts/actions_receipt.py`）。
- `ai_undo.finalize(snapshot, receipt=…)` 以回执为准；拿不到回执才退回延迟读盘并记警告。
- `undo` 持**同一把目标锁**做校验与写回。
- 写入成功但索引登记失败 → `pending_repair` + 旁标文件（`ai_undo/pending.json`），
  撤销如实回「已提交，撤销记录待修复」，不谎报可撤销。

### P1 账单与附件

- 账单以 `business_key`（`<物品 id>@<账期>`）幂等：先落支出、再推进度、最后发通知；
  支出写失败时**不推进度**，重启后按业务键补齐，正确账期恰有一条支出。
- 附件待删按 `初始索引 ∪ 新增 − 最终选择` 的差集重算（原来记的是"点过删除"的名单，
  删后加回同内容会删掉仍被引用的实体）；回滚只针对本次真正新增的实体。

### P1 UI 成功判定与命令验收

- 作业勾选：`set_status()` 返回回滚快照，`save()` 失败时回滚内存 + 弹提示 + 不广播。
- `add_task` / `add_course` / `add_plan` / `add_habit` 按**显式提交的字段**回读
  （截止 / 星期 / 节次 / 计划日期 / 周期 / 时长），与写入端同一归一化口径（`ERRORS #060`）。

### P1 门禁可信

- `check_quality.py` 三态：`STATE_OK` / `VIOLATION` / `UNAVAILABLE`。
  严格模式下**两者都退出非零**；缺工具、退出码非零且无输出、输出无法解析、
  git 不可用全部如实报出（原来都退化成"通过"或"跳过"）。
- 密钥扫描：未安装 → `UNAVAILABLE`；跑了但结果不可信 → `VIOLATION`。
- `acceptance_check.py`：合成数据工厂（两学期 + 三件套 + 库存 / 记账），`data/` 缺失时
  走合成路径；目录哈希**排除 `settings.ini`**（原来递归哈希真实数据目录）。
- CI：push 覆盖 `master` + `dev`；pytest 带 `--cov-fail-under=50`；新增合成验收步骤；
  `ci_local.py` 与 CI 参数一致（有 `tests/test_ci_alignment.py` 守着）。

### P2 Hermes 投递账本

- 账本三态 `pending` / `delivered` / `uncertain`；产出只记 `pending`，
  投递端带 `--ack` 才转 `delivered`；窗口过完仍 `pending` → `uncertain` + 警告提示人工核对。
- 不自动重试（消息没有幂等键，重发等于重复打扰）。
- 老账本无 `state` 列 → 按 `delivered` 读，不重放历史提醒。

### P1 模型载入分类与轮询探针（第二轮补做）

审计原文这条此前**没做**，本轮补上（`src/models/base.py` + `src/services/data_manager.py`）：

- **五种状态分开**（原来只捕获 `JSONDecodeError`，另外三种从别处炸开）：
  | 状态 | 处理 |
  |---|---|
  | 缺失 | 建默认值 |
  | **暂时不可读**（`OSError`，重试 5×50ms） | 抛 `Unreadable`：**不留档**、用默认值继续、**禁止写入** |
  | 编码错误（非法 UTF-8） | 留档 + `DataCorrupted` |
  | 解析失败 / **schema 不符**（根是数组、`_version` 类型错、顶层键类型错） | 留档 + `DataCorrupted` |
  | 未来版本 | **不是损坏**：只警告、只读、不写回 |
- 新增 `Unreadable` 与 `DataCorrupted` **分开**：前者重试，后者留档。
  `reload()` 成功后解除写入封锁（一次占用不该永久失写）。
- 轮询探针 `abs(st_mtime - last) > 0.1` → **`st_mtime_ns` 不等即重载**：
  审计复现的"mtime 只变 50ms 的内容更新被漏掉"由 `test_polling_precision.py`
  用 `os.utime` 确定性钉死（把实现改回旧阈值，该用例必红 ✓ 已实测）。
- 缺失也算一种状态（探针记 0），删除/重建不再被吞掉；一直缺失不会反复触发刷新。
- **按域通知**：`DataManager.DOMAIN_OF` 是"文件名 → 事件域名"的唯一映射，
  轮询发现 `tasks.json` 变了就发 `task`（一个面板刷新），不再一律 `external` 全刷；
  只有"变了但没登记域名"才退回 `external`（保守全刷）。

**验收脚本的两个可执行性前提**（不修就"跑不起来"，而跑不起来的门禁等于没有门禁）：

1. 用户开着真实应用时，默认命名的单实例管道会被它接走 → 脚本被误判成"第二实例"并中止。
   改走 `ARCHITECTURE` §3 已规定的测试通道 `LIFE_ASSISTANT_SINGLE_INSTANCE_KEY`，
   并在 `import src.app` **之前**赋值（key 在模块导入时求值），名字带 pid 防并发互抢。
2. Windows 控制台默认 cp936，回执里的 `¥` 会让 `print` 抛 `UnicodeEncodeError`，
   脚本死在第七节半途。新增 `_configure_stdout()`（与 `check_quality.py` 同一处理）。
3. 顺带补 `_teardown()`：脚本自己拉起的 App 要关窗口 / 停定时器 / 关单实例服务，
   否则解释器退出时报 "QThread: still running"。

守卫：`tests/test_acceptance_runnable.py`（5 条：独立管道存在且在 import 之前、名字唯一、
UTF-8、可重复调用、收尾被调用）。

**补齐"本地与 CI 用不同数据"的另一半**：`test_shipped_data_files_are_versioned_and_valid`
只校验本机 `data/`，而拆仓库后 `data/` 不随代码仓库走 → CI 里那条直接 `skip`，
"schema 合法"在两端根本不是同一个结论。新增 `tests/test_data_schema_synthetic.py`（20 条）：
用 `tmp_path` 让**每个模型**真的落盘，断言可解析 + 是对象 + 带 `_version`，并核对
`actions_core._schema_version()` 与模型 `supported_version` 一致（不一致时 AI 写完的文件
会被判成"版本比本程序新"而拒绝保存）。
