# 2026-10-19 R2：精确余量贯穿所有读取端

## 起因

`PLAN.md` P22 批次一第二条（`REVIEW.md` R2）。上一轮把**算法**修对了
（`apply_consume` + `remaining_doses`，1 盒 24 片扣 1 片不再丢 23 片），
但**真值没有贯穿读取端**：

| 读取端 | 原来显示 | 为什么 |
|---|---|---|
| 界面（库存卡） | `x0 (0次)` | `inventory_panel.py` 拿 `quantity × doses_per_unit` 现拼 ✗ |
| CLI `lookup_item` | `0盒 (0片)` | `_item_extra()` 同样现算 ✗ |
| AI 摘要（提示词） | `0盒` | `inventory_prompt()` 只给盒数 ✗ |
| CLI 补货正文 | `(0盒)` | `cmd_need_restock()` 同上 ✗ |

于是**用户和模型都以为没库存了** ✗ —— 底层对，读出来错。

## 改法：真值只有一处，展示口径也只有一处

`src/models/inventory.py` 新增两个静态方法（与 `effective_status` 同级）：

- `stock_parts(item) -> (整包装数, 散装小单位, 每包装小单位)` —— **一律从 `remaining_doses` 推**；
- `stock_text(item) -> str` —— 纯文本口径（CLI / AI 摘要用）：
  `3包` / `2盒` / **`0盒（剩 23 片）`**（整包装为 0 时散装必须说出来）。

界面单独一层（要 i18n）：新文件 **`src/ui/panels/inventory_text.py`** 的 `quantity_text(it)`，
走 `stock_parts` + `tr()` → `x0 (23次)`。

> 为什么新开一个文件：`inventory_panel.py` 已经**顶到尺寸上限**（文件 800 行 / 类 400 行，
> 存量在 `scripts/quality_baseline.json`，规则是"只允许减少"）—— 往里塞会**直接红** ✗。
> 顺手把数量文字从面板里搬出来，类和文件都变小了。

四个读取端全部改成走这两处：

| 位置 | 改动 |
|---|---|
| `inventory_panel.py` | 删掉 `_format_quantity`（搬进 `inventory_text.py`）；两处调用改 `quantity_text(it)`；**删掉调用处那段 `quantity * dpu`** ✗ |
| `actions_cmds_items.py` | `_item_line` / `_item_extra` / `cmd_need_restock` 三处改走 `InventoryModel.stock_text` / `remaining_doses` |
| `ai_prompts.py` | `inventory_prompt` 改走 `stock_text`（**首次**在这个模块引入 import —— 它此前是纯字符串模块 ✓） |
