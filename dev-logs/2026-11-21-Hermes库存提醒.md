# Hermes 微信库存查询与续费/补买提醒

日期：2026-11-21。复杂度：L3（修改多个 Python 文件、工具契约与数据查询路径）。

## 目标与流程

让微信 Hermes 通过现有 `daily_task_query` / `daily_task_update` 受控读取和操作“有什么”模块，
并在用户查询时返回可执行的续费/补买提醒。查询走只读 inventory 投影；写操作走固定桥接器、
Actions CLI、`ai_guard`、快照和回读验收。

## 变更

- 查询增加 `inventory` 与 `restock` 范围：可查看物品、数量、位置、分类、有效状态及当前提醒。
- 续费提醒覆盖 7 日内到期或已过期会员（含自动续费核对）；补买提醒覆盖低库存、预计用完和临期商品。
- 查询只读取库存模型数据，不读取私有会员手机号；只对学校侧、未豁免且状态需处理的物品生成提醒。
- 微信写操作开放新增、修改和消耗库存；删除需要交互式审批，微信桥没有审批界面，因此不暴露删除动作。
- 桌面端每日提醒文案区分续费与补买，并用当前有效状态，而不是可能过期的保存快照。
- 更新 Hermes 与架构说明，明确微信提醒按需查询、不会定时主动推送，且部署副本需复制源码并重启网关。

## 验证

- 隔离数据目录测试覆盖 inventory/restock 查询、有效状态重算、手机号不泄漏、库存新增/修改/消耗、
  删除拒绝、验证回执及桌面提醒文案。所有写入测试使用 `sandbox`。
- 聚焦测试：`tests/test_hermes_actions.py`、`tests/test_hermes_plugin.py`、
  `tests/test_reminder_restock.py`。

## 部署状态

本次改动仅使工作区插件源码具备库存能力；部署副本尚需更新并重启 Hermes 网关后，微信端才会获得这些新工具。
微信主动提醒没有实现；现有续费/补买消息在用户查询时返回，桌面端沿用每日提醒。
