# 2026-10-19 R1/A1：收尾漏洞 —— 所有出口统一走 `_finish()`

## 起因

`PLAN.md` P22 批次一第一条。两份独立审查都把它排第一：

- `.pytest_cache/review-20261019/REVIEW.md` **R1**
- `MD-files/AI助手参考资料/AI助手专项审查.md` **A1**

## 病根（已核对代码 ✓）

`AIWorker.run()` 里"模型自己收尾"这条路：

```python
if not instructions:
    if self._handle_no_instructions(...):
        continue
    finished_normally = True
    return                      # ✗ 直接 return
```

而 `_handle_no_instructions()` 在停止时**自己 emit**（`finished_with_instructions` /
`finished` / `error`）✗ —— **绕过了 `_finish()`** ✓。

后果：`_finish()` 里那套"汇报权归代码"（`_status_note` 的**写失败量化**、**部分完成上报**、
**没改数据告警**）在"模型自己说完了"这条路上**全部失效** ✗✗ —— 而这恰恰是最常走的出口 ✓。

两条桩复现（审查给的）：
1. 命令返回 `ERROR`，模型接着说"已记录" → 用户只看到"已记录" ✗；
2. 一条命令都没发、连说"已记录" → 追问耗尽后**正常完成** ✗。

> 这说明：**"护栏函数写对了" ≠ "所有出口都经过它"** ✗ —— 这正是专项审查 A8
> （"能证明函数存在，不能证明退出路径经过它"）说的那类问题 ✓。

## 改法

1. `run()` 里"模型自己收尾" → **`break`**（不再 `return`）✓，`final_text = text` ✓
   → 落到末尾**唯一一处** `_finish()` ✓；
2. `_handle_no_instructions()` → 改名 **`_should_continue()`**，**只返回 bool** ✓
   （决定继续/停止），**不发任何最终信号** ✓；
3. 累计状态（`all_instructions` / `write_failures` / `ok_count` / `wrote_data`）
   **提到 `try` 之外初始化** ✓ → `except` 里也把它们带上：
   异常若发生在**部分写入之后**，用户仍能看到"写失败 N 条" ✓（原来只报异常 ✗）。

## 教训

**"函数写对了"和"所有出口都经过它"是两件事** ✗。
判据应该是**出口数量**：`run()` 里有几处 `emit`？—— 只该有 `_finish()` 那一处 ✓。
（这条与 REVIEW §"机械门禁的边界"、专项 A8 是同一类：**能证明符号存在，不能证明路径经过** ✓。）
