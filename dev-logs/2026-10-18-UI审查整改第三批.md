# 2026-10-18 UI 审查整改 · 第三批（AI 面板 + 字体单位）

## U3 · AI 历史消息切主题后不可读（已修）

**问题**（审查实测）：`ai_panel.append_message()` 把**当前主题的颜色烤进 HTML**，然后拼到
一个大 `QLabel` 上；`refresh_theme()` 只改外壳 QSS。所以浅色下建的消息切到深色后，
文字仍是深色 —— 几乎不可读。

**修法**：消息**按结构存**（`self._messages`：角色 / 正文 / 是否占位），渲染时现取颜色。

| 改动 | 说明 |
|---|---|
| `self._messages` + `_render_messages()` | 追加与换主题都走同一条渲染路径 |
| `_message_html(msg)` | 颜色**每次现取**；用户正文与占位走 `html.escape`，AI 正文走 `_md_to_html` |
| `refresh_theme()` | 末尾加 `self._render_messages()` —— 换主题必须重画历史 |
| 占位替换 | 原来是拿 `<!--ph-->` 做字符串手术（找 `</div></div>` 配对）；现在真回复到达时按**结构**去掉占位 |

顺带把另一半也修了（上一步已做）：`_md_to_html` 先 `html.escape` 再做 markdown ——
否则用户正文里的 `<b>` 会被 Qt 当标签渲染。

⚠ 审查建议的"气泡交给真实 QWidget 布局、文本区只负责富文本"是更大的重构，**没做**，
留在第四批评估（当前仍是单 `QLabel` + HTML，但已可重画）。

## U5 · 字号混用 point / pixel（已修）

**问题**：QSS 用 `font-size: Npx`，而 16 处调用点写 `QFont(FONT_CN, SIZE_X)` ——
`QFont` 的第二个参数是 **point**（本机 20pt ≈ 27 逻辑像素），两套单位混用，标题/标签/输入
内容比例不一致。

**修法**：新增 `theme.font(size, weight=None)`，内部走 **`setPixelSize`**，与 QSS 同单位；
`init_theme()` 里设全局字体也改成 `setPixelSize`。16 处调用点（12 个文件）改成 `font(...)`，
`ruff --fix` 顺手清掉 25 个失效导入。

**为什么选像素而不是 point**：令牌的意图就是像素（QSS 一直这么用），改 point 会让字整体变大
（14pt ≈ 19px），而审查明确说"不要逐页调小字号抵消单位错误"。所以统一到像素，**QFont 侧向
QSS 看齐**。
