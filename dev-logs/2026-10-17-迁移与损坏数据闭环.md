# 2026-10-17 迁移与损坏数据闭环（审查 #5）

## 起因

审查指出两件事：① `migrate()` 找不到迁移函数时**照样把 `_version` 抬上去**（隔离目录实测
`migrate(99)` 变成版本 99）；② 普通模型读坏 JSON 直接抛异常，而学期注册表读坏 JSON 却按
空数据重建 —— **错误策略不一致**，而且损坏现场会被直接覆盖。

## 变更清单

| 文件 | 改动 |
|---|---|
| `src/models/base.py` | `migrate()` **逐步执行** + **缺一步就拒绝**（`MigrationUnavailable`，一个字节不写）+ 任一步失败 `MigrationFailed` 且文件保持原样；新增 `supported_version` 属性；`load()` 区分"损坏"（`DataCorrupted` + **留档**）与"版本比本程序新"（只警告、不动数据）；`_quarantine()`；`__init__` 捕获 `DataCorrupted` → 用默认值继续 + 记 `recovered_from` |
| `src/models/semester_paths.py` | `read_registry()` 坏 JSON → **留档**（`<name>.corrupt-<时间戳>.json`）后按空重建；日志从 warning 改 **error** |
| `src/services/data_manager.py` | `_log_recoveries()`：把留档的损坏文件汇总成一条 ERROR 日志 |
| `.gitignore` | 加 `*.corrupt-*.json`（留档文件不进版本库）|
| `tests/test_migration_guard.py`（新）| 5 条：缺迁移步骤拒绝且不动文件 · 逐步执行 · 某步失败不写 · 坏 JSON 留档 + 默认值可用 · 注册表坏 JSON 留档 |

**三种情况现在分开了**：文件**缺失** → 建默认值；**损坏** → 留档 + 默认值 + ERROR 日志；
**版本比本程序新** → 只警告、不改动（不再"假装迁过了"）。
