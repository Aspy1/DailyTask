## 1. 第一步：全量审查与基础整改

### 1.1 审查方法

1. **静态**：`compileall` / `ruff` / `check_ui_tokens --strict --check-px` /

2. **逐文件**：models → services → UI → scripts → tests，重点看

3. **动态**：先跑全量 `pytest` 取基线，再用真实 UI 走查验证。

## 2. 第二步：全量回归 + AI 助手可靠性

### 2.1 真实启动的沙箱

新增 `LIFE_ASSISTANT_DATA_DIR`（`src/services/paths.py`）：应用、CLI、天气缓存、
设置面板统一读同一个数据目录。`scripts/ui_walkthrough.py` 因此可以：

1. 在临时目录种数据（不碰用户 `data/`）；
2. 构造真实 `MainWindow`（Settings / DataManager / AIService / PluginManager）；
3. 最后用**真实 `main.py` 子进程**离屏启动一次，确认首屏不崩。

### 2.2 走查覆盖（39 项）

- 10 个面板逐个切换（含新增「考研备考」）+ 日/周视图 + 主题深/浅 + AI 面板开合；
- 任务完成/按课程筛选、习惯打卡、近期安排三态、支出/存钱、库存状态/版本切换；
- AI 四个离线场景（脚本化 provider，不联外网）：
  1. **正常执行**：输出 `add_task` → 落库 → 界面【已执行】+ 验收信息；
  2. **只说不动**：连续说"已记录"但不发命令 → 界面明确"数据没有任何改动"；
  3. **命令失败**：`--quantity -1` 被校验拒绝 → 界面明确"N 条写命令没有生效"；
  4. **批量写**：课程 + 作业 + 支出 → 三条都落库，事实块逐条列出。

结果：**39/39 通过**。走查抓到 3 个真实问题（均已修）：

- `_version` 缺失 → 第一次 UI 保存被误判冲突（#053）；
- 自绘 `ToggleSwitch` 没有 `clicked` → 真实应用（有插件时）启动即崩（#054）；
- 支出事实行没有对象名（`add_expense` 的 label 为空）。

### 2.3 AI 助手可靠性：从"模型说"到"代码验收"

对齐仓库内 `Agent Reliability Engineering Design Guide` 的几条：

| 原则 | 落地 |
|---|---|
| 模型不是 reporter | 最终事实块由 `ai_ledger` 按**命令结果 + 回读验收**生成；模型的话只作说明 |
| 格式正确 ≠ 业务成立 | `ai_verify` 执行后**回读数据**；每条写命令都有验收器 |
| 部分完成要量化 | 被轮次/时限切断时输出"执行 N 条 / 写成功 K 条" |
| 提示不是安全机制 | 写数据强制点在 `actions.py`（校验 + 同名同位置护栏 + 备份） |
| 循环检测 | 同一批命令重复 → 告知 → 收束；不是只靠 max_turns |
| 预算显式 | 5 轮 + 墙钟上限（默认 90s），到点不再发新请求 |

**验收面**：原先只有 6 个验收器，现在覆盖**全部写命令**（作业/课程/考试/习惯/日程/
记账/财务/位置/库存/考研）。`test_every_write_command_has_a_verifier` 会在新增写命令
忘记补验收器时变红；`test_all_write_commands_verify_against_real_data` 把每条命令真跑一遍；
`test_claiming_ok_without_the_data_is_a_mismatch` 钉住"命令说 OK 但数据没变 → mismatch"。

## 3. 第三步：大三学生备考 11408 的一个月

### 3.1 场景假设

- 大三，目标 2027-12-25 初试；每天可投入约 4–5 小时。
- 工作日：数学一 120 + 408 90 + 英语一 40 + 政治 30 分钟；
- 周末：模考（数学/408 交替）+ 错题复盘；
- 每天记 1–2 道错题；每天复习到期错题；每周一次模考。

### 3.2 一个月模拟结果（`scripts/study_month_simulation.py`）

| 指标 | 数值 |
|---|---|
| 学习记录 | **104 条** |
| 总时长 | **7600 分钟（126.7 小时）** |
| 各科 | 数学 3440 / 408 2620 / 英语 880 / 政治 660 分钟 |
| 错题 | 新增 60 道，完成复习 **192 次**，月底待复习 0 |
| 周节奏 | 每周 1760 分钟，工作日 5/7 达标（周末低于 220 目标） |
| 模考 | 数学 95→105，408 90→98 |
| 倒计时 | 距目标 178 天 |

模拟暴露的真实问题：**周末只有 180 分钟，低于每日 220 的目标** → 连续达标只有 3 天。
这不是模型/统计错，而是计划本身需要调整 —— 软件把"周末塌陷"直接显示出来了。

### 3.3 新功能：为什么是这些

| 需求 | 现有能力为什么不够 | 新实现 |
|---|---|---|
| 每天各科学了多久 | 习惯只有"打没打卡"，日程只有"几点做什么"，都没有分钟数 | `study.json` 的 `sessions[]` + `log_study` |
| 错题下次哪天复习 | 日程要手工建每一条，且不会按记忆曲线推进 | `mistakes[]` + 1/2/4/7/15/30 天阶梯 + `due_reviews()` |
| 模考趋势 | 考试模块只有"考试日期"，没有分数 | `mocks[]` + `add_mock` + 最近 5 次 |
| 还剩多久 | 状态栏只有"备考 N 科" | `target_date` + `countdown()` + 面板倒计时 |
| 这周各科够不够 | 没有"目标 vs 实际" | 面板进度条 + `week_by_subject()` |
| 问 AI "今天该复习什么" | 模型可能自己编 | `study_summary` 输出代码算好的清单，AI 只能转述 |

### 3.4 新功能的入口

- **面板**：侧边栏「考研备考」→ 倒计时 / 今日待复习（复习/掌握按钮）/ 本周各科进度 /
  最近模考；四个弹窗（学习/错题/模考/目标）。
- **命令**：`log_study` · `add_mistake` · `review_mistake` · `master_mistake` ·
  `add_mock` · `list_mistakes` · `study_summary` · `study_set_target`。
- **AI**：提示词新增「考研备考」段；所有写命令有验收器；
  问进度只能用 `study_summary`，**不许自己加总**。
- **同步**：`study.json` 已加入 `git_sync.DATA_FILES`（跨学期共享，随数据仓库同步）。

### 3.5 仍需的功能（模拟结论，按价值排序）

1. **错题图片/公式**（数学一刚需）：当前题干/思路是单行文本；
2. **模考失分表**：从"分数"到"哪一章丢分"；
3. **周计划生成**：按错题主题/章节给出本周目标，而不是只记录；
4. **番茄钟/专注计时**：`log_study` 是事后记录，不能自动计时（仓库已有 `plugins/pomodoro`
   但当前禁用，可作为下一步）；
5. **睡眠/精力**：考研后期"什么时候学"比"学多久"更重要，需要和日程/习惯联动；
6. **按章节/题型细分学习记录**：目前只有科目 + 分钟。

## 7. 结论与边界

- 第一步的审查不是"跑一遍工具"：走查与真实启动额外抓出了 3 个静态检查看不见的问题
  （#053/#054/#057），都已补回归测试。
- AI 可靠性的核心不是提示词，而是**代码验收 + 汇报权归代码**：
  现在每条写命令都有回读验收，模型说"已完成"不再能绕过事实块。
- 考研模块只做**确定性、可验证**的部分（时长、间隔复习、模考、倒计时）；
  不做"AI 替用户做学习规划"这类不可靠能力；缺口已在 §3.5 列明。
- 已知边界：错题暂不支持图片/公式、模考没有失分表、没有番茄钟/睡眠记录；
  这些是下一步的自然扩展，不影响当前功能闭环。
