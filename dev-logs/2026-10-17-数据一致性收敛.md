# 2026-10-17 数据一致性收敛（路线 B：修订号 + 单写者）

**起因**：一次外部审查（隔离目录复现 + 63 项针对性测试）指出 6 项缺口。逐条核实：
**诊断属实**（证据在 `PLAN.md` P17 的表里），但**药方**（SQLite 事务 + 跨进程锁）对这个
项目代价过大 —— 会丢掉 `data/*.json` 的可读、可被 skill/CLI 编辑、可 git 版本化、
可 backup/restore。经用户拍板走**路线 B**：不换存储，补冲突检测 + 单写者。

## 决策依据（为什么不是 SQLite）

| 维度 | 现状（JSON 文件） | SQLite 文档库 | SQLite 关系库 |
|---|---|---|---|
| 事务 / 跨进程锁 | ✗（本次要补的） | ✓ | ✓ |
| 行级并发 | ✗ | ✗ | ✓ |
| 新增字段 | **零迁移** | 零迁移 | **每次都要迁移** |
| AI/CLI/skill/人 同一命令面 | ✓ | ✓（若带 JSON 镜像） | ✗（拆成 ORM/SQL） |
| git 审计 + 任意粒度回滚 | ✓ | 需镜像 | 需镜像 |
| 迁移成本 | — | 1-2 天 | 数天~一周 |

关键判断：**收益（跨进程并发写）在这个项目里几乎不会被触发** —— 应用是单实例
（`R-006`），外部编辑按项目约定要关应用；而 `file_path` 被 47 处引用、11 个测试文件按
JSON 断言、`git_sync` 按 `data/*.json` 同步、`data-fix-scheduler` skill 直接教人改 JSON。
换存储等于把这些全部重做，换来的能力用不到。

## 变更清单

### 阶段 1（2026-10-17 完成）

**1. 退出不再覆盖外部改动**（审查 #1 的最现实路径）

- `DataManager.flush_on_exit()`：逐模型比对**磁盘内容**（不是 mtime —— 应用自己保存
  也会动 mtime，只比 mtime 会把"刚保存完就退出"误判成冲突）
  - 文件缺失 → 正常落盘
  - 磁盘 == 内存 → **不碰文件**
  - 读不出来（损坏）或内容不同 → **不覆盖**：我方版本写到 `data/backup/exit_conflict/`
    （`data/backup/` 已在 `.gitignore`）+ 日志 + `save_conflict` 信号；原文件（含损坏现场）
    保持原样
- `app.py` 的 `_restart` / `quit` 改调 `flush_on_exit()`
- `save_all()` 保留但改注释：**无条件**写，只给"明确没有外部写入"的场合（测试 /
  `acceptance_check.py`）

**2. 撤销只回滚本次安排涉及的 `plans`**（审查 #3）

- 旧：`copy2` 备份整份 `daily_logs.json`，撤销整份覆盖 → 连带回滚期间产生的打卡记录
  （`logs`）与自定义提醒（`reminders`），还绕开原子写
- 新：`plans_snapshot()` 记**安排前 / 安排后**两份 `plans` 深拷贝；撤销时先按磁盘
  `reload()`，**校验当前 `plans` 是否仍等于"安排后"** —— 不等就拒绝并提示（期间被手动
  调整或另一轮 AI 改过），相等才只写回 `plans` 并走模型 `save()`（原子写）
- 实现放在 `ui/widgets/schedule_actions.py`（`plans_snapshot` / `undo_arrange`）：
  `schedule_view.py` 是 SIZE 存量超限项，而门禁**只防新增/加重** —— 搬出后文件/类/
  `__init__` 三项都回到基线内

**踩到的坑（值得记）**：回滚逻辑搬走后 `QMessageBox` 换到了 `schedule_actions` 模块，
而测试的 monkeypatch 还打在 `schedule_view` 上 → **真弹了模态框 → 测试挂死 900s**。
教训：搬函数时，被 patch 的**模块级名字**（Qt 类、常量）要跟着搬测试目标。

**验证**：407 passed（401 → 407）· ruff 0 · 门禁 14 项全绿（SIZE 新增/加重 **0**）·
令牌 0 违规

### 阶段 2（2026-10-17 完成）：保存冲突检测

**方案改动（重要）**：计划里写的是 `_rev` 号，实现时改成**磁盘内容指纹**（sha256 +
`sort_keys`）。原因：`_rev` 要求**每个写入方都配合维护**，而真实的并发来源恰恰是
`scripts/actions_core.py`（AI 路径）、skill（直接改 JSON）、手工编辑 —— 这三条都不会去
bump `_rev` ✗ → 冲突**照样静默通过**，等于没修。指纹不依赖任何一方配合，且与键序无关
（"只是被重新格式化过"不算改动）。

- `BaseJsonModel`：`load()` 记下磁盘指纹；`save()` 写前重读比对 → 不一致**不写**，
  交 `on_conflict` 回调，返回 `False`。**不抛异常** —— `save()` 有二十来个调用点
  （各面板改完就存），抛出去会把 UI 打崩。
- `DataManager`：`_attach_conflict_hook()` 给每个模型装回调（模型不是 QObject，用回调）；
  ⚠ **切学期会重建 courses/tasks/exams**，`_bind_semester_models()` 里必须重装，否则
  新学期那三个模型丢回调 → 冲突又变回静默覆盖（已写测试钉住）。
- 冲突处理：我方版本留 `data/backup/save_conflict/`（与阶段 1 的退出路径**同一个目录**，
  阶段 1 的 `exit_conflict` 已改名统一）+ 发 `save_conflict` → `MainWindow` 弹窗告知。
- 新增 `tests/test_save_conflict.py`（5 条）：直接编码审查的复现（A/B 两实例）、
  同实例连续保存不误报、仅重新格式化不算冲突、DataManager 留副本 + 信号、切学期后回调仍在。

**验证**：412 passed（407 → 412）· ruff 0 · 门禁全绿
