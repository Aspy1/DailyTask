## 关键问题与修复

### A. 线程安全 / 并发

| 问题 | 修复 |
|---|---|
| `ReminderService._send_email()` 在主线程同步 SMTP（超时 10s → UI 冻结） | 新增 `services/email_sender.py`：后台串行队列；`_send_email` 只入队；退出时 `shutdown()` 最多等 2s |
| 设置页「发送测试邮件」同样同步 SMTP | 新增 `ui/widgets/email_test_worker.py`（QThread），结果信号回主线程 |
| `AIService.send_message` 无忙守卫，第二次发送会覆盖正在运行的 `QThread` 引用 | `_busy` 标记 + 线程 `finished` 才释放；忙时明确报错，不覆盖 |
| `settings.ini` 每次保存整份写回（运行中每分钟一次）→ 外部改动被静默回滚（ERRORS #044） | 脏键跟踪 + 保存时重读磁盘只覆盖脏键 + `.tmp`/`os.replace` 原子写 + fsync |
| `actions.run_in_process` 用 `redirect_stdout` 改全局 `sys.stdout` | 改为 `actions_core.emit()` + **线程局部**缓冲 `capture_output()`；命令输出互不串线 |
| `GitSync._on_done` 不清理 `_worker`，下次 `isRunning()` 访问已删除 C++ 对象 | 完成后置 `None` |
| `semester_paths.ensure_current` 非原子写注册表，可能被对方读成损坏 | 原子写 + 文件锁 + mtime 缓存 + 损坏前重试一次 |

### B. 性能 / 启动路径

| 问题 | 修复 |
|---|---|
| 应用关几天再开：`_catch_up()` 逐分钟扫几万次，启动卡死 | 补跑窗口上限 12h（`CATCHUP_MAX_MINUTES`），超出直接跳过并记日志 |
| 提醒服务每分钟 `settings.save()` | `last_reminder_check` 每 5 分钟落一次；余额无告警时不写设置 |
| 系统提示词缓存键用 `len(...)`：同长度修改不失效 → AI 拿旧事实 | 缓存键改为相关数据内容的 sha256 |
| 提示词里的计划清单取 **最早** 10 天 | 改为「今天起」最近 10 天 |
| 提示条每次刷新都重读 5 个 JSON + 构造 `CourseModel` | `HintBar` 直接读 `DataManager` 内存模型；`today_hints` 支持预加载参数 |
| `exam_panel` / `habit_panel` 等全量重建控件 | 保持现状（数据量小），但修掉 `PluginsPanel`/`SettingsPanel` 重建时不 `deleteLater` 的控件泄漏 |
| `_quiz`… `_course_table` 等无 | —— |

### C. 正确性 / 静默失败

| 问题 | 修复 |
|---|---|
| 习惯「添加附属事项」弹窗复制了父类 UI，却调用不存在的方法 → **打开即 AttributeError** | 删除整段复制代码；`保存为模板`按钮真正写模板 |
| 日程日视图课程不显示教室 | 从 `time_slots[].location` 读取 |
| 日视图打卡后卡片不刷新（hash 未含 `done`） | `done` 进入内容指纹；`add_habit_to_slots` 直接带完成状态 |
| 课程右键「布置了作业」把 prompt 塞进 `data_changed` → 无人消费且全界面刷新 | 新增 `ScheduleView.fill_ai_prompt` → `MainWorkspace` → `MainWindow` 正式信号链 |
| 「查看事项」切到任务面板后没有筛选 | `TaskPanel.filter_by_course()` 补 `_refresh()` |
| `CoursePanel` 定义了两次 `_week_number`（前者死代码） | 删除重复定义 |
| `TaskModel._auto_archive()` 只改内存 → 退出写成冲突副本 | 有改动立即 `save()` |
| ID 生成两套并存（最小空位 / max+1），删除后会复用 ID | `gen_id` / `TaskModel` / `ExamModel` 统一 `next_id`（max+1）；物品用 `item_seq` 单调计数 |
| 损坏的单个数据文件会让 `DataManager.reload_all()` 抛异常 | 逐个隔离 `DataCorrupted`，其余文件照常重载 |
| 新版数据文件（`_version` 更高）仍会被旧程序 `save()` 覆盖 | 载入时记录 `_loaded_future`，普通保存拒绝；显式 `migrate()` 例外 |
| `send_digest` 购物需求判断 `status == "need"`（实际是「需购/不足」）→ 永不显示 | 用 `InventoryModel.effective_status()` + 兼容旧值；顺带用共享课程规则、容错坏 JSON、从 slot 读教室 |
| 考试日期可输入任意字符串 | 弹窗校验 `YYYY-MM-DD`；新增 i18n 文案 |
| 天气降水字段脏数据会让详情弹窗/AI 提示词崩 | `float()` 容错 |
| 设置页天气统计按 `__file__` 猜 data 目录 | 优先 `DataManager.data_dir` |
| 单实例启动先 `removeServer()` 再连接 → 可能破坏正在运行实例 | 先 connect，确认失败后才 remove |
| 虚拟品类默认位置判断用旧名「虚拟品类」 | 同时认「订阅」/「虚拟品类」 |
| `add_item` 的 `--runs-out-months 0` 被新校验拒绝（0=今天合法） | 范围改 `0..600` |
