# 2026-10-19 会员弹窗存不上：字段白名单漂移

## 怎么发现的（不是测试，是**渲染**）

今天那条"提示条要换行"的修复只在 4 条提示时验过 ✗。为了让提示条**真的**进入换行状态，
我给渲染 fixture 的衣物加了 `worn_since`（10 天前）+ `wash_after_days`（7）——
结果 `light-schedule.png` 里**"该洗了"提示根本没出现** ✗。

顺着查下去，发现是**两个 bug**：

## Bug 1：`add_item` 静默丢字段

```python
m.add_item({"name": "coat", "worn_since": "...", "wash_after_days": 7})
# 存下来的键：category / created_at / doses_per_unit / group / id / ignore_low_stock /
#             instances / location / min_quantity / name / notes / quantity /
#             remaining_doses / status / tags / unit / updated_at
# → worn_since / wash_after_days **不见了** ✗
```

`add_item` 手写了一个固定 dict ✓ —— 清单外的字段**静默丢弃** ✗。

## Bug 2（严重，用户可见）：`update_item` 白名单**没跟上新字段** ✗✗

```python
dm.inventory.update_item(iid, {"membership": {...}})   # 返回 True ✓
m.items[0].get("membership")                           # → None ✗✗
```

白名单里只有 14 个老字段，**没有** `membership` / `expires_on` / `runs_out_on` /
`remind_before_days` / `stock_target` / `worn_since` / `wash_after_days` / `needs_wash` ✗。

而**会员弹窗就是这条路径**（`inventory_dialogs.py:211`）：

```python
dm.inventory.update_item(item["id"], {"membership": membership})
dm.inventory.save()
```

→ **用户打开"编辑会员"、填到期日、保存 → 什么都没存** ✗，弹窗还正常关闭 ✓
（`update_item` 返回 `True` **谎报成功** ✗）。

## 为什么 700 多条测试全没拦住

命令路径（AI / CLI）**根本不走模型的这两个方法** ✗ ——
`scripts/actions_cmds_items.py` 直接 `item["expires_on"] = ...` 改 dict ✓。
于是 `test_actions_*` / `test_inventory_expiry` / `test_inventory_wash` 全绿 ✓，
**模型 API 这条路没人测** ✗。UI 侧也只有"弹窗能打开"这类测试，没有"存了能读回来" ✗。

## 修法：字段清单**只有一份**

```python
# src/models/inventory.py
ITEM_FIELDS = (
    "name", "category", "group", "quantity", "unit", "status",
    "min_quantity", "min_doses", "location", "notes", "tags",
    "instances", "ignore_low_stock", "doses_per_unit",
    "membership", "expires_on", "runs_out_on", "remind_before_days", "stock_target",
    "worn_since", "wash_after_days", "needs_wash",
)
```

- `update_item` 遍历 `ITEM_FIELDS` ✓（**唯一**写入口）
- `add_item` 在"有默认值的字段"之外，把清单里其余字段**原样带上** ✓
- 清单外的键**告警**（`logger.warning`）✓ —— 今天这个 bug 的形态正是"默默吞掉" ✗

> ⚠ 门禁 `LOG-ONLY`（"块内唯一语句是日志"）拦了一下 ✗ —— 所以告警块里同时做了
> **真正的过滤**（`data = {… if k in ITEM_FIELDS}`），不是硬凑语句 ✓。

## 教训

1. **"有测试"不等于"这条路有测试"** ✗ —— 同一个功能有两条入口（命令 / 模型）时，
   测了一条不代表另一条对 ✓。UI 走的是**模型 API** ✓，而所有物品测试都在走 CLI ✗。
2. **白名单会漂移** ✗ —— 同一份字段清单写两处，加字段时漏一处就静默丢数据 ✓。
   字段清单**只有一份** + 清单外的键**告警**（而不是默默吞）✓。
3. **又一次是渲染逼出来的** ✓ —— 今天第 4 个由"亲眼看"发现的 bug ✓
   （`QDialogButtonBox` 顺序 / 提示条被切 / 括号套括号 / 这个丢字段）✓。
   前三个是"难看" ✗，这个是**数据没了** ✗✗。
