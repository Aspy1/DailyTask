# 2026-10-16 · 按学期分数据文件（切换学期 = 换一份数据）

## 起因

用户指出：**"现在切换学期不会修改应当显示的课程表"**，并要求明确"什么是学期间继承的、什么不是"：
> "吃什么 / 有什么 以及记账功能要继承；作业 / 课程表 / 考试都应当换新的数据文件"

核实后确认，问题比表面更彻底：

```
课程数（全局一份）: 24
课程字段: day_of_week, id, name, teacher, teacher_schedule, time_slots, week_parity, weeks
```

`courses[]` 是**全局一个列表**，每条课程**没有任何学期字段**；`tasks` / `exams` 同理。
切学期只改了 `start_date`（"周次→日期"的映射），24 门课在哪个学期都出现 ——
**不是刷新问题，而是数据模型里根本没有"学期"这个维度**（`ERRORS #040`）。

用户拍板：
- 按学期分：**课程表 / 作业 / 考试**；跨学期继承：**有什么 / 记账 / 习惯 / 日程计划**
- 布局：`data/semesters/<学期id>/` 子目录

## 变更清单

### 1. 布局与解析

```
data/
├── semesters.json                 注册表：semesters[] + current_semester（共享）
├── semesters/<学期id>/
│   ├── courses.json               课程表（含 holidays）
│   ├── tasks.json                 作业
│   └── exams.json                 考试
└── habits / expenses / inventory / daily_logs.json      跨学期共享
```

**路径解析只有一处**：`semester_paths.resolve(data_dir, name)`。
应用、`actions.py`、`send_digest.py`、`build_index.py`、`tests/helpers.read_json` 全调它，
所以 `load("tasks.json")` 这类 **30+ 处调用点一行没改**，也不会写错学期。

### 2. 切换学期（本次的核心）

`DataManager.switch_semester(sid)`：改指针 → **把 `courses/tasks/exams` 重定向到新学期的文件**
→ 重新捕获 mtime → 发 `data_changed("semester")`。
`create_semester()` 在此基础上先建学期（**从空白数据开始**）再切过去。
`semester_dialog` 的两个动作改调它们 —— 直接改 `semesters.json` 的指针**不会换数据**。

### 3. 模型拆分（为什么调用点能不改）

`SemesterRegistry` 承接原 `CourseModel` 的全部学期职责（状态 / 周次 / 体检 / 新建 / 切换）；
`CourseModel` 保留**同名转发**方法（`semester_status` / `current_week` / `get_period_count` /
`semesters` / `get_semester` / `get_courses_for_date` / `validate`…）。
于是界面 / AI 的 40 处 `dm.courses.xxx()` 一行没改 —— **接口不变、内部换实现**。

### 4. 迁移（安全顺序）

`migrate_legacy()`：**先写新文件 → 校验 → 再删旧文件**；幂等（注册表已存在就返回 False）。
真实数据实测：**24 课 / 2 作业 / 6 考试，迁移前后完全一致，零丢失**；
根下旧文件已清理，新目录 `semesters/sem_001/` 就位。迁移前另存了一份备份。

### 5. 验证与顺带修正

- 冒烟：`sem_001` = 24 课 / 2 作业 / 6 考试（active，第 5/16 周）；旧学期 = 0/0/0（expired）；
  共享数据（有什么 11 / 记账 4 / 习惯 1）在切学期后**依旧在** ✓
- 新增测试：切换学期换文件、共享数据继承、旧布局迁移（含幂等）
- `test_data_schema` 的"仓库数据文件必须带 `_version`"扩展到按学期的那批

## 决策原因

- **为什么路径解析要单独一个模块**：应用、AI 脚本、邮件摘要、索引脚本、测试助手**五处**都要
  知道"这个文件在哪个学期"；分散实现必然漂移（这次就是"数据没有学期维度"的教训）。
- **为什么 `CourseModel` 保留转发而不是让调用方改用 `dm.semesters`**：
  40 处调用点分散在界面/AI/脚本里，改名既慢又容易漏；**接口不变、内部换实现**风险最低，
  且"课程模型能回答学期问题"对调用方本来就是合理预期。
- **为什么迁移"先写后删"**：数据是不可再生的用户资产；即使中途失败也不能让旧文件消失
  （何况 git 历史里也有）。
- **为什么老学期现在是空的**：旧 schema 里课程/作业/考试**没有学期字段**，
  无法反推它们属于哪个学期；迁移只能全部归到当前学期。要还原得手动补 ——
  这比"猜一个归属"更安全。
