# 2026-10-18 库存数据集切换（本地 / 家）

用户需求：换季时会把部分衣物**邮寄回家**、来年再寄回，所以「有什么」需要一份**平行**的
存放清单，并且能切换查看。家那份**不区分位置**（用户口径）。

## 先审查需求（没有直接照做）

需求里有两处需要先问清：

1. "**场景**切换"这个词在本项目里是**已弃用**的旧功能（2026-10-16 弃用，位置并进了天气设置
   `migrate_legacy_scene_location()`）。所以这次是**新做**一套数据视图，不是复活它 —— 已确认。
2. "平行数据集"有两种落法，代价差很多，我列了对比让用户选。

## 方案对比：为什么用"归属字段"而不是"两个平行文件"

| | 归属字段（**采纳**） | 两个平行文件 |
|---|---|---|
| 写入路径 | **一个字都不用改** —— 单写者、进程内锁 + OS 文件锁、磁盘指纹冲突检测、`_LOADED` 路径绑定、写前备份、git 同步范围全部原样适用 | DataManager 要多管一个模型（`_models()` / 3s 轮询 mtime / `save_all` / 冲突钩子）、git 同步清单加一项、`actions_core` 路径解析改成"数据集感知"、`list_backups`/`restore` 要知道新文件 |
| 移动（寄回家） | 改一个字段：id 不变、原子写、不可能丢件 | 跨文件 = 一个文件删 + 另一个文件加，**两个文件两把锁**，中间失败就是丢件或重件；且两份文件各自都有 `i_001`，id 空间撞车 |
| 打穿既有加固 | 否 | **是** —— 正好绕开刚做完的原子性与冲突检测 |

用户选了归属字段。

## 用户口径（四个决定）

1. 归属字段方案；
2. 家那份**不显示位置**（不留占位值，位置字段留空）；
3. 要"寄回家 / 寄回来"这个**移动动作**（界面 + AI 命令）；
4. 家那一边**不参与补货提醒**（托盘/邮件/`need_restock` 都不看它）。

## 变更清单

### 数据形状（`src/models/inventory.py`）

纯**新增**，老文件靠自愈补齐：

- 物品加 `dataset`（`local` / `home`，缺失 → `local`）
- 顶层加 `current_dataset`（缺失 / 非法 → `local`）
- `locations[]` 语义收窄为**本地数据集**的位置词表（家不使用位置）

**没有升 `_version`** —— `Q-E4` 明确写了 `_migrate_vN_to_vM` **仍是骨架**（尚无历史版本迁移
需求），而且 `migrate()` 在生产代码里**从未被调用**（只有测试调它）。这份文件既往加字段
（`categories` / `locations` / `instances` / `doses_per_unit` / `min_doses`）全是自愈式补键，
本次沿用同一做法。

新增 API：`current_dataset` / `set_dataset()` / `dataset_of()` / `visible_items` /
`allowed_locations` / `move_item()`。

⚠ `items` 保持"**全部**物品"的语义不变（`visible_items` 才是当前数据集）：按 id 的增删改必须
能跨数据集找到条目（`move_item` 就靠这个），习惯面板挑关联物品、全量验收、探针也都读 `items`，
改语义会波及无关功能。展示类调用点（面板 / AI 提示词）改用 `visible_items`。

### 命令层（`actions_cmds_items.py` / `actions_core.py` / `actions_cli.py`）

- `--dataset` 加到 `add_item` / `update_item` / `lookup_item`；取值合法性在 `SPECS` 统一校验
- `add_item` 不传 `--dataset` → 落在**当前数据集**（界面看哪边就写哪边）
- `update_item --dataset` = **寄回家 / 寄回来**（改归属字段）
- 家数据集 + `--location` → **拒绝且不写任何文件**（R-002 的入口校验）
- `lookup_item` 默认只看当前数据集；`--dataset home` 看另一边，`all` 两边都看；
  家那边的条目输出带 `[家]` 且**不显示位置**
- `need_restock` 与 `lookup_item --restock yes` 只看本地
- `set_locations` / `add_location` 回执里标明是**本地**的词表

### 提示词（`ai_prompts.py` / `ai_service.py`）

- `_inventory_prompt()` 只给 `visible_items`，用 `allowed_locations`（家 → 无位置行），
  并在开头标出**【当前数据集】本地 / 家** —— 否则模型会把寄回家的东西当成手边的
- 提示词缓存键纳入 `current_dataset` + `visible_items` 条数（否则切数据集后提示词不失效）
- 补了 `--dataset` 的用法示例 + 一条规则（"寄回家 = `update_item --dataset`，**不要**删了再建"）

### 界面（`inventory_panel.py` / 新 `inventory_dialogs.py` / i18n）

- 工具栏加数据集按钮（标签＝当前数据集，点开菜单选）—— 照同一工具栏里 `_cat_btn` /
  `_tag_btn` 的现成做法，**不新建控件规范**（`design/INDEX.md` 里"表里没有"的那种情况：
  已有按钮规范够用，所以没有新开条目）
- 卡片对家那一边**不显示位置**
- 右键菜单加"寄回家 / 寄回来"（只对真实条目显示 —— 实例卡片传进来的是合成 dict）
- 切换后清掉一切"按视图"的状态（分类/标签筛选、分页、展开）
- i18n 新增 4 个键（`dataset_local` / `dataset_home` / `action_send_home` / `action_send_back`）

## 关键设计决定（连同理由）

1. **`current_dataset` 存在数据文件里**，不存 `settings.ini` —— 界面与命令行读**同一份**，
   AI 的 `add_item` 才能默认跟随你正在看的那一边（存 settings 的话命令行看不见，AI 会
   在你看"家"的时候把新物品写进本地，**静默写错数据集**）。这同 `semesters.json` 的
   `current_semester` 是同一个套路。
   - 代价：切换会改数据文件 → 触发一次 git 同步提交（与切学期同样的噪声，可接受）
2. **AI 不能切数据集**（没有 `set_dataset` 命令）：切换是**界面**的事，避免模型偷偷改掉
   用户的视图。它要动另一边，就显式 `--dataset home`。
3. **家那边的物品保留 `location` 值但不显示**（不在移动时清空）：寄回来时还能落回原格位，
   也不静默丢信息。"不显示"是用户口径，"保留"是我的取舍 —— 要改成清空是一行的事。
4. **补货永远只看本地**：`need_restock` 不看 `current_dataset`（家里的东西在这儿买不了）。

## 设计时发现的陷阱（差点写进去）

`update_item` 的 `--dataset` **不能**像 `add_item` 那样"没传就回退成当前数据集" ——
用户正看着"家"的时候改一条本地物品的数量，就会被**误搬**到家里。

所以拆成两个 helper：`_requested_dataset()`（只取显式值，供 `update_item`）与
`_dataset_arg()`（显式值 or 当前数据集，供 `add_item` / `lookup_item`）。
回归测试 `test_update_without_dataset_does_not_move_anything` 钉住这条。
