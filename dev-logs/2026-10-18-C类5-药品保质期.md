# 2026-10-18 C 类第 5 项：药品保质期 / 常备药

`PLAN.md` P20 的"常备药"：药品加**保质期**，临期提醒换新。

## 复用"到期日驱动状态"，只多接一个字段

代码里已有这个形状（会员 `expires_on`、`runs_out_on`）。所以这一项**不是新机制**，
只是往 `derive_status` 的链里再加一环：

```
会员到期 → 药品保质期（新） → 预估用完 → 数量/片数
```

## ⚠ 偏离 P20 原计划（要说清）

P20 原话："到**保质期的 3/4** 时提醒（临期换新）"。

**这算不出来** —— "3/4 保质期"需要**生产日期**，而我们只有**到期日** ✗。
所以老实改成"**到期前 N 天**"（`remind_before_days`，默认 7）：

```python
lead = item.get("remind_before_days") or RENEW_WARNING_DAYS   # 默认 7 天
return "不足" if days <= int(lead) else "充足"
```

> 与 C 类第 1 项（`runs_out_on`）同一处理：**算不出来的精确，不如说清楚的近似** ✓

## 与 `runs_out_on` 的语义差别（刻意分开）

| 字段 | 含义 | 触发 |
|---|---|---|
| `runs_out_on` | 预计**用完** | 要**补货** |
| `expires_on` | 保质期**到期** | 要**换新**（临期） |

机制相同、语义不同，所以**分开两个字段** ✓ —— 提示词里明确写"别用 `--runs-out` 记保质期"。
